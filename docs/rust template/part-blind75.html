Arrays & Hashing
Every problem in this category is a variation on "trade an O(n²) nested loop for an O(n) hashmap/hashset pass" — the algorithmic idea is usually the easy part. In Rust the real interview signal is how you get there: choosing HashSet::insert's boolean return over a separate contains check, using the Entry API instead of manual get/insert dances, and deciding up front whether a function should take ownership of a Vec/String or just borrow it.
hashmap single pass Easy LC 1
Two Sum
Given an array of integers nums and an integer target, return the indices of the two numbers that add up to target. Assume exactly one solution exists, and you may not use the same element twice.

Example: nums = [2, 7, 11, 15], target = 9 → [0, 1] (because nums[0] + nums[1] == 9).
Signature
fn two_sum(nums: Vec<i32>, target: i32) -> Vec<i32> { /* ... */ }
Solution — reveal after attempting (O(n) one-pass hashmap) 
use std::collections::HashMap;

fn two_sum(nums: Vec<i32>, target: i32) -> Vec<i32> {
    let mut seen: HashMap<i32, usize> = HashMap::new();
    for (i, &n) in nums.iter().enumerate() {
        let complement = target - n;
        if let Some(&j) = seen.get(&complement) {
            return vec![j as i32, i as i32];  // found the pair — complement was seen at index j
        }
        seen.insert(n, i);  // record AFTER checking, so we never pair an element with itself
    }
    panic!("no two sum solution");  // problem guarantees exactly one solution exists
}

fn main() {
    assert_eq!(two_sum(vec![2, 7, 11, 15], 9), vec![0, 1]);
    assert_eq!(two_sum(vec![3, 2, 4], 6), vec![1, 2]);
    assert_eq!(two_sum(vec![3, 3], 6), vec![0, 1]);
    println!("two-sum: all assertions passed");
}
Complexity: O(n) time, O(n) space — one pass, checking for the complement before inserting the current element.
Rust angle: The natural brute force is O(n²) nested loops with no ownership complications at all — which is exactly why interviewers watch how you reach for HashMap. Note the check-then-insert order: checking seen.get(&complement) before seen.insert(n, i) is what stops you from pairing an element with itself when target == 2 * n. A candidate who reaches for the Entry API (seen.entry(n).or_insert(i)) unprompted for a follow-up like "now count duplicates" is showing real HashMap fluency.

Contains Duplicate
Given an integer array nums, return true if any value appears at least twice in the array, and false if every element is distinct.

Example: nums = [1, 2, 3, 1] → true (the value 1 appears at indices 0 and 3).
Signature
fn contains_duplicate(nums: Vec<i32>) -> bool { /* ... */ }
Solution — reveal after attempting (O(n) hashset) 
use std::collections::HashSet;

fn contains_duplicate(nums: Vec<i32>) -> bool {
    let mut seen: HashSet<i32> = HashSet::new();
    for n in nums {
        if !seen.insert(n) {
            return true;  // insert returns false if the value was already present
        }
    }
    false
}

fn main() {
    assert_eq!(contains_duplicate(vec![1, 2, 3, 1]), true);
    assert_eq!(contains_duplicate(vec![1, 2, 3, 4]), false);
    assert_eq!(contains_duplicate(vec![1, 1, 1, 3, 3, 4, 3, 2, 4, 2]), true);
    assert_eq!(contains_duplicate(vec![]), false);  // empty input, no duplicates possible
    println!("contains-duplicate: all assertions passed");
}
Complexity: O(n) time, O(n) space — one pass, one hashset.
Rust angle: HashSet::insert returns a bool — true if the value was newly inserted, false if it was already present — which lets you do the "have I seen this?" check and the recording of it in a single call instead of the two-lookup contains()-then-insert() pattern many candidates default to. Also note the for n in nums loop consumes nums by value (moves ownership in); if a follow-up needed the original vector afterward, you'd switch to for &n in &nums to iterate by reference instead.
hashmap counting Easy LC 242
Valid Anagram
Given two strings s and t, return true if t is an anagram of s — i.e. it uses exactly the same characters, each the same number of times.

Example: s = "anagram", t = "nagaram" → true (same multiset of letters, just reordered).
Signature
fn is_anagram(s: String, t: String) -> bool { /* ... */ }
Solution — reveal after attempting (O(n) char-count hashmap) 
use std::collections::HashMap;

fn is_anagram(s: String, t: String) -> bool {
    if s.len() != t.len() {
        return false;  // different lengths can never be anagrams
    }
    let mut counts: HashMap<char, i32> = HashMap::new();
    for c in s.chars() {
        *counts.entry(c).or_insert(0) += 1;
    }
    for c in t.chars() {
        let entry = counts.entry(c).or_insert(0);
        *entry -= 1;
        if *entry < 0 {
            return false;  // t has more of this char than s did
        }
    }
    counts.values().all(|&v| v == 0)
}

fn main() {
    assert_eq!(is_anagram("anagram".to_string(), "nagaram".to_string()), true);
    assert_eq!(is_anagram("rat".to_string(), "car".to_string()), false);
    assert_eq!(is_anagram("a".to_string(), "ab".to_string()), false);  // different lengths
    assert_eq!(is_anagram("".to_string(), "".to_string()), true);  // empty strings are trivially anagrams
    println!("valid-anagram: all assertions passed");
}
Complexity: O(n) time, O(1) space (bounded alphabet) or O(n) space in the general Unicode case.
Rust angle: The counts map deliberately uses a signed i32 instead of usize/u32 — decrementing during the t pass can legitimately go negative when t has more of a char than s did, and that negative value is the early-exit signal. Using an unsigned counter there would cause an integer underflow panic in a debug build the moment a mismatched character shows up, turning a normal "not an anagram" case into a crash instead of a clean early return.

Group Anagrams
Given an array of strings strs, group the anagrams together and return the groups (in any order, groups and elements within a group can be in any order).

Example: ["eat", "tea", "tan", "ate", "nat", "bat"] → [["bat"], ["nat", "tan"], ["ate", "eat", "tea"]] — each inner group shares the same sorted-letter key.
Signature
fn group_anagrams(strs: Vec<String>) -> Vec<Vec<String>> { /* ... */ }
Solution — reveal after attempting (O(n·k log k) sorted-key hashmap) 
use std::collections::HashMap;

fn group_anagrams(strs: Vec<String>) -> Vec<Vec<String>> {
    let mut groups: HashMap<Vec<u8>, Vec<String>> = HashMap::new();
    for s in strs {
        let mut key: Vec<u8> = s.bytes().collect();
        key.sort_unstable();  // sorted bytes are the canonical anagram key
        groups.entry(key).or_insert_with(Vec::new).push(s);
    }
    groups.into_values().collect()
}

fn sorted_groups(mut v: Vec<Vec<String>>) -> Vec<Vec<String>> {
    for g in v.iter_mut() {
        g.sort();
    }
    v.sort();
    v
}

fn main() {
    let result = group_anagrams(vec![
        "eat".to_string(), "tea".to_string(), "tan".to_string(),
        "ate".to_string(), "nat".to_string(), "bat".to_string(),
    ]);
    let expected = vec![
        vec!["ate".to_string(), "eat".to_string(), "tea".to_string()],
        vec!["nat".to_string(), "tan".to_string()],
        vec!["bat".to_string()],
    ];
    assert_eq!(sorted_groups(result), sorted_groups(expected));

    let result2 = group_anagrams(vec!["".to_string()]);
    assert_eq!(result2, vec![vec!["".to_string()]]);  // single empty string, its own group

    let result3 = group_anagrams(vec!["a".to_string()]);
    assert_eq!(result3, vec![vec!["a".to_string()]]);

    println!("group-anagrams: all assertions passed");
}
Complexity: O(n·k log k) time where k is the max string length (dominated by sorting each key), O(n·k) space.
Rust angle: The key is built from s.bytes().collect::<Vec<u8>>() rather than sorting chars() — bytes are cheaper to sort for ASCII input and, more importantly, Vec<u8> implements Hash/Eq out of the box so it drops straight into a HashMap key with zero ceremony. Also note the ordering constraint: the sorted key must be computed before s is moved into groups.entry(key).or_insert_with(...).push(s), since s is consumed there — reversing that order is a borrow-checker error, not a logic bug, and is a good example of Rust forcing you to think about move order that other languages let you ignore.
hashmap bucket sort / heap Medium LC 347
Top K Frequent Elements
Given an integer array nums and an integer k, return the k most frequent elements. You may return the answer in any order.

Example: nums = [1, 1, 1, 2, 2, 3], k = 2 → [1, 2] (1 appears 3 times, 2 appears twice — both beat 3's single appearance).
Signature
fn top_k_frequent(nums: Vec<i32>, k: i32) -> Vec<i32> { /* ... */ }
Solution — reveal after attempting (O(n) bucket sort by frequency) 
use std::collections::HashMap;

fn top_k_frequent(nums: Vec<i32>, k: i32) -> Vec<i32> {
    let total = nums.len();
    let mut counts: HashMap<i32, usize> = HashMap::new();
    for n in nums {
        *counts.entry(n).or_insert(0) += 1;
    }
    // bucket[i] = values that appear exactly i times; max possible frequency is the input length,
    // NOT the distinct-value count, since duplicates can all cluster into one key
    let mut buckets: Vec<Vec<i32>> = vec![Vec::new(); total + 1];
    for (val, freq) in counts {
        buckets[freq].push(val);
    }
    let mut result = Vec::new();
    for freq in (0..=total).rev() {
        for &val in &buckets[freq] {
            result.push(val);
            if result.len() == k as usize {
                return result;
            }
        }
    }
    result
}

fn sorted(mut v: Vec<i32>) -> Vec<i32> {
    v.sort_unstable();
    v
}

fn main() {
    assert_eq!(sorted(top_k_frequent(vec![1, 1, 1, 2, 2, 3], 2)), vec![1, 2]);
    assert_eq!(top_k_frequent(vec![1], 1), vec![1]);
    assert_eq!(sorted(top_k_frequent(vec![1, 2], 2)), vec![1, 2]);  // tie: both appear once, k equals distinct count
    assert_eq!(sorted(top_k_frequent(vec![4, 4, 4, 6, 6, 1, 1, 1, 1], 2)), vec![1, 4]);
    println!("top-k-frequent: all assertions passed");
}
Complexity: O(n) time, O(n) space — bucket sort by frequency avoids the O(n log n) of sorting by count.
Rust angle: The bucket array must be sized by nums.len() (the total element count), not by counts.len() (the number of distinct values) — sizing it off the distinct-value count is a genuinely easy mistake that compiles fine and then panics with an index-out-of-bounds the moment duplicates cluster into fewer distinct keys than their own frequency (e.g. nine numbers spread across only three distinct values). This is exactly the kind of off-by-a-wrong-variable bug Rust's array bounds checking catches loudly at runtime instead of silently corrupting memory. A BinaryHeap<Reverse<(usize, i32)>> capped at size k is the classic O(n log k) alternative if the interviewer wants to avoid the O(n) auxiliary bucket array.
prefix/suffix product Medium LC 238
Product of Array Except Self
Given an integer array nums, return an array answer where answer[i] equals the product of all elements of nums except nums[i]. You must solve it in O(n) time without using the division operator.

Example: nums = [1, 2, 3, 4] → [24, 12, 8, 6] (e.g. answer[0] = 2*3*4 = 24).
Signature
fn product_except_self(nums: Vec<i32>) -> Vec<i32> { /* ... */ }
Solution — reveal after attempting (O(n) time, O(1) extra space prefix/suffix pass) 
fn product_except_self(nums: Vec<i32>) -> Vec<i32> {
    let n = nums.len();
    let mut result = vec![1; n];
    let mut prefix = 1;
    for i in 0..n {
        result[i] = prefix;
        prefix *= nums[i];  // prefix holds product of all elements before i
    }
    let mut suffix = 1;
    for i in (0..n).rev() {
        result[i] *= suffix;
        suffix *= nums[i];  // suffix holds product of all elements after i
    }
    result
}

fn main() {
    assert_eq!(product_except_self(vec![1, 2, 3, 4]), vec![24, 12, 8, 6]);
    assert_eq!(product_except_self(vec![-1, 1, 0, -3, 3]), vec![0, 0, 9, 0, 0]);
    assert_eq!(product_except_self(vec![2, 3]), vec![3, 2]);  // minimal two-element case
    assert_eq!(product_except_self(vec![0, 0]), vec![0, 0]);  // two zeros still yields all zeros, no division needed
    println!("product-except-self: all assertions passed");
}
Complexity: O(n) time, O(1) extra space beyond the required output vector (two passes, no division).
Rust angle: Writing directly into result[i] across two separate passes (rather than allocating parallel prefix/suffix vectors) works cleanly here because result is a Vec you already own outright — no aliasing rules get in the way of mutating it index-by-index in two different loops. The other genuine trap: i32 multiplication overflows silently in release builds (wrapping) but panics in debug builds via an overflow check — worth flagging to an interviewer that a production version handling large arrays might want i64 accumulators or explicit checked_mul.
hashset O(n) Medium LC 128
Longest Consecutive Sequence
Given an unsorted array of integers nums, return the length of the longest run of consecutive integers (they don't need to be contiguous in the array, just present in the set of values). The algorithm must run in O(n) time — sorting first is not allowed.

Example: nums = [100, 4, 200, 1, 3, 2] → 4 (the run 1, 2, 3, 4).
Signature
fn longest_consecutive(nums: Vec<i32>) -> i32 { /* ... */ }
Solution — reveal after attempting (O(n) hashset, only start counting at run boundaries) 
use std::collections::HashSet;

fn longest_consecutive(nums: Vec<i32>) -> i32 {
    let set: HashSet<i32> = nums.into_iter().collect();
    let mut best = 0;
    for &n in &set {
        // only start counting from the beginning of a run, so each run is visited once
        if set.contains(&(n - 1)) {
            continue;
        }
        let mut len = 1;
        let mut cur = n;
        while set.contains(&(cur + 1)) {
            cur += 1;
            len += 1;
        }
        best = best.max(len);
    }
    best
}

fn main() {
    assert_eq!(longest_consecutive(vec![100, 4, 200, 1, 3, 2]), 4);
    assert_eq!(longest_consecutive(vec![0, 3, 7, 2, 5, 8, 4, 6, 0, 1]), 9);
    assert_eq!(longest_consecutive(vec![]), 0);  // empty input has no sequence
    assert_eq!(longest_consecutive(vec![1, 2, 0, 1]), 3);  // duplicate value must not inflate the run length
    println!("longest-consecutive: all assertions passed");
}
Complexity: O(n) time, O(n) space — each number is only ever the inner loop's starting point once, across the whole run.
Rust angle: nums.into_iter().collect::<HashSet<i32>>() consumes the input vector to build the set — perfectly idiomatic here since the original order was useless anyway and the duplicate-collapsing behavior of HashSet is exactly what the "duplicate value must not inflate the run length" edge case needs for free. Iterating a HashSet with for &n in &set gives zero ordering guarantees, which is precisely why the "is n - 1 in the set?" guard isn't just an optimization — without it you'd re-walk every run from every one of its members and blow the O(n) bound entirely.
string design Medium LC 271
Encode and Decode Strings
Design an algorithm to encode a list of strings into a single string, and a decode that recovers the exact original list. The encoded form must survive any character content — including the delimiter you choose — and empty strings.

Example: ["lint","code","love","you"] encodes to some string s, and decode(s) returns the same four strings in order.
Signature
fn encode(strs: Vec<String>) -> String { /* ... */ }
fn decode(s: String) -> Vec<String> { /* ... */ }
Solution — reveal after attempting (length-prefix encoding) 
fn encode(strs: Vec<String>) -> String {
    // length-prefix: "<len>#<payload>" per string — unambiguous even with '#' in content
    let mut out = String::new();
    for s in strs {
        out.push_str(&format!("{}#{}", s.len(), s));
    }
    out
}

fn decode(s: String) -> Vec<String> {
    let bytes = s.as_bytes();
    let mut i = 0;
    let mut result = Vec::new();
    while i < bytes.len() {
        let mut j = i;
        while bytes[j] != b'#' {
            j += 1;
        }
        let len: usize = std::str::from_utf8(&bytes[i..j]).unwrap().parse().unwrap();
        let start = j + 1;
        let end = start + len;
        result.push(String::from_utf8(bytes[start..end].to_vec()).unwrap());
        i = end;
    }
    result
}

fn main() {
    let input = vec!["lint".into(), "code".into(), "love".into(), "you".into()];
    assert_eq!(decode(encode(input.clone())), input);

    let with_delim = vec!["a#b".into(), "".into(), "#".into(), "hello#world".into()];
    assert_eq!(decode(encode(with_delim.clone())), with_delim);

    let empty: Vec<String> = vec![];
    assert_eq!(decode(encode(empty.clone())), empty);

    println!("encode-decode-strings: all assertions passed");
}
Complexity: O(n) time and space where n is the total number of characters across all strings — one pass to encode, one pass to decode.
Rust angle: A naive join-on-'#' falls apart the moment a payload contains '#' (or is empty). Length-prefixing ("{len}#{payload}") is the classic fix, and in Rust you almost always decode over as_bytes() rather than chars() so the length you stored (byte length from String::len) lines up with the slice you take back — mixing char-count lengths with byte slices is a common UTF-8 footgun. Also notice both sides take/return owned String/Vec<String>: this is a serialization boundary, so ownership transfer is the honest API rather than fighting lifetimes through the encoded blob.

Two Pointers
These problems converge two indices from opposite ends of a (usually sorted) collection toward each other. In Rust the pointers themselves are almost always usize, which is unsigned — decrementing a pointer that's already at 0, or computing hi - lo when lo > hi, doesn't wrap around like it might in C; it panics on subtraction overflow in a debug build. Loop bounds and guard order matter more here than in languages with signed indices.

Valid Palindrome
Given a string s, return true if it reads the same forward and backward after converting all uppercase letters to lowercase and removing all non-alphanumeric characters.

Example: s = "A man, a plan, a canal: Panama" → true (ignoring punctuation/spaces/case, it's "amanaplanacanalpanama").
Signature
fn is_palindrome(s: String) -> bool { /* ... */ }
Solution — reveal after attempting (two pointers over a filtered char buffer) 
fn is_palindrome(s: String) -> bool {
    let chars: Vec<char> = s.chars().filter(|c| c.is_alphanumeric()).map(|c| c.to_ascii_lowercase()).collect();
    let mut lo = 0;
    let mut hi = chars.len();
    if hi == 0 {
        return true;  // empty after filtering counts as a palindrome
    }
    hi -= 1;
    while lo < hi {
        if chars[lo] != chars[hi] {
            return false;
        }
        lo += 1;
        hi -= 1;
    }
    true
}

fn main() {
    assert_eq!(is_palindrome("A man, a plan, a canal: Panama".to_string()), true);
    assert_eq!(is_palindrome("race a car".to_string()), false);
    assert_eq!(is_palindrome(" ".to_string()), true);  // no alphanumeric chars at all
    assert_eq!(is_palindrome("0P".to_string()), false);  // mixed alnum types, not equal ignoring case
    println!("valid-palindrome: all assertions passed");
}
Complexity: O(n) time, O(n) space for the filtered buffer.
Rust angle: Rust Strings are UTF-8 byte sequences, not directly indexable by character position — there's no s[i] for a char, so collecting into Vec<char> first is the idiomatic move before doing index-based two pointers. The other trap is initializing hi to chars.len() and needing to decrement it once before the loop guard: doing hi = chars.len() - 1 directly instead would panic on subtraction overflow the instant the filtered string is empty, which is exactly why the explicit hi == 0 early return exists here.
two pointers sorting Medium LC 15
3Sum
Given an integer array nums, return all unique triplets [nums[i], nums[j], nums[k]] (with distinct indices) such that they sum to zero. The result must not contain duplicate triplets.

Example: nums = [-1, 0, 1, 2, -1, -4] → [[-1, -1, 2], [-1, 0, 1]].
Signature
fn three_sum(nums: Vec<i32>) -> Vec<Vec<i32>> { /* ... */ }
Solution — reveal after attempting (sort + fixed anchor + two pointers, O(n²)) 
fn three_sum(mut nums: Vec<i32>) -> Vec<Vec<i32>> {
    nums.sort_unstable();
    let n = nums.len();
    let mut result = Vec::new();
    for i in 0..n {
        if i > 0 && nums[i] == nums[i - 1] {
            continue;  // skip duplicate anchors to avoid duplicate triplets
        }
        if nums[i] > 0 {
            break;  // sorted ascending: once the anchor is positive, no triplet can sum to zero
        }
        let (mut lo, mut hi) = (i + 1, n - 1);
        while lo < hi {
            let sum = nums[i] + nums[lo] + nums[hi];
            if sum < 0 {
                lo += 1;
            } else if sum > 0 {
                hi -= 1;
            } else {
                result.push(vec![nums[i], nums[lo], nums[hi]]);
                lo += 1;
                hi -= 1;
                while lo < hi && nums[lo] == nums[lo - 1] {
                    lo += 1;  // skip duplicate low values
                }
                while lo < hi && nums[hi] == nums[hi + 1] {
                    hi -= 1;  // skip duplicate high values
                }
            }
        }
    }
    result
}

fn main() {
    assert_eq!(three_sum(vec![-1, 0, 1, 2, -1, -4]), vec![vec![-1, -1, 2], vec![-1, 0, 1]]);
    assert_eq!(three_sum(vec![0, 1, 1]), Vec::<Vec<i32>>::new());  // no triplet sums to zero
    assert_eq!(three_sum(vec![0, 0, 0]), vec![vec![0, 0, 0]]);
    assert_eq!(three_sum(vec![]), Vec::<Vec<i32>>::new());  // empty input, no triplets possible
    println!("3sum: all assertions passed");
}
Complexity: O(n²) time (O(n log n) sort + O(n) anchors × O(n) two-pointer scan), O(n) or O(log n) space depending on the sort's internals.
Rust angle: Taking mut nums: Vec<i32> by value (rather than &mut Vec<i32>) means the function takes full ownership and can call sort_unstable() directly with no extra borrow ceremony — a clean signal that you understand when to take ownership versus borrow. The three separate duplicate-skip guards (i > 0, lo < hi && nums[lo] == nums[lo-1], lo < hi && nums[hi] == nums[hi+1]) all exist specifically to stop usize subtraction from underflowing at index 0 or overflowing past n-1 — in a language with signed indices you could get away with a lazier bounds check.
two pointers greedy Medium LC 11
Container With Most Water
Given n non-negative integers height where each represents a vertical line at that index, find two lines that together with the x-axis form a container holding the most water. Return the maximum area.

Example: height = [1, 8, 6, 2, 5, 4, 8, 3, 7] → 49 (the lines at indices 1 and 8, height 7, width 7).
Signature
fn max_area(height: Vec<i32>) -> i32 { /* ... */ }
Solution — reveal after attempting (O(n) two pointers, always move the shorter line) 
fn max_area(height: Vec<i32>) -> i32 {
    let mut lo = 0;
    let mut hi = height.len() - 1;
    let mut best = 0;
    while lo < hi {
        let width = (hi - lo) as i32;
        let area = width * height[lo].min(height[hi]);
        best = best.max(area);
        // moving the taller line can only shrink the width without helping the limiting (shorter) side
        if height[lo] < height[hi] {
            lo += 1;
        } else {
            hi -= 1;
        }
    }
    best
}

fn main() {
    assert_eq!(max_area(vec![1, 8, 6, 2, 5, 4, 8, 3, 7]), 49);
    assert_eq!(max_area(vec![1, 1]), 1);
    assert_eq!(max_area(vec![4, 3, 2, 1, 4]), 16);  // best pair is the two equal end lines
    assert_eq!(max_area(vec![1, 2, 1]), 2);
    println!("container-with-most-water: all assertions passed");
}
Complexity: O(n) time, O(1) space — each pointer only ever moves inward, so the total work is linear.
Rust angle: height.len() - 1 computed once for the initial hi quietly relies on the problem's guarantee that n >= 2 — worth saying out loud in an interview, since it would underflow-panic on a single-element or empty input under different constraints. The (hi - lo) as i32 cast is unavoidable Rust ceremony: usize and i32 don't mix in arithmetic, so every width/index-derived quantity that needs to multiply against a signed height value pays an explicit cast tax that C++ or Python would let you skip silently (and sometimes incorrectly).
// Blind 75 · Sliding Window
Sliding Window
A sliding window tracks a range [left, right] over a sequence and grows/shrinks it based on some running condition, instead of re-scanning from scratch. In Rust the window bounds are usize indices into a Vec<char>/Vec<u8> you build up front — you rarely slice a &str mid-algorithm (byte-offset slicing on non-ASCII input can panic if it splits a UTF-8 character), and for small fixed alphabets a stack-allocated [i32; 26] frequency array is both faster and more idiomatic than reaching for a HashMap.

fn length_of_longest_substring(s: String) -> i32 {
    let chars: Vec<char> = s.chars().collect();
    let mut seen: HashSet<char> = HashSet::new();

    best as i32

fn character_replacement(s: String, k: i32) -> i32 {
    let chars: Vec<u8> = s.bytes().collect();
    let mut counts = [0i32; 26];
    let mut left = 0;
    let mut max_freq = 0;  // highest single-char count seen in any window so far
    for right in 0..chars.len() {
        let idx = (chars[right] - b'A') as usize;
        counts[idx] += 1;
        max_freq = max_freq.max(counts[idx]);
        let window_len = (right - left + 1) as i32;
        // chars that need replacing = window size minus the count of the most frequent char
        if window_len - max_freq > k {
            let left_idx = (chars[left] - b'A') as usize;
            counts[left_idx] -= 1;
            left += 1;
        }
    }
    (chars.len() - left) as i32
}

fn main() {
    assert_eq!(character_replacement("ABAB".to_string(), 2), 4);
    assert_eq!(character_replacement("AABABBA".to_string(), 1), 4);
    assert_eq!(character_replacement("A".to_string(), 0), 1);  // single char, no replacements needed or allowed
    assert_eq!(character_replacement("AAAA".to_string(), 0), 4);
    println!("longest-repeating-char-replacement: all assertions passed");
}
Complexity: O(n) time, O(1) space — a fixed 26-slot frequency array instead of a hashmap.
Rust angle: [0i32; 26] — a stack-allocated, Copy, zero-hashing fixed-size array — is a strong idiomatic-Rust signal over reaching for HashMap<char, i32> whenever the alphabet is small and known (here, uppercase ASCII). Indexing into it requires the very Rust-specific (chars[right] - b'A') as usize dance: subtracting two u8 byte values, then casting to usize for indexing, since Rust won't implicitly convert between integer types. Given two strings s and t, return the smallest substring of s that contains every character of t (including matching duplicate counts). Return an empty string if no such window exists.

use std::collections::HashMap;

fn min_window(s: String, t: String) -> String {
    if t.is_empty() || s.len() < t.len() {
        return String::new();
    }
    let s_bytes: Vec<u8> = s.bytes().collect();
    let mut need: HashMap<u8, i32> = HashMap::new();
    for b in t.bytes() {
        *need.entry(b).or_insert(0) += 1;
    }
    let required = need.len();  // number of distinct chars in t that must be fully satisfied
    let mut window: HashMap<u8, i32> = HashMap::new();
    let mut formed = 0;  // number of distinct chars currently satisfied in the window
    let mut left = 0;
    let mut best_len = usize::MAX;
    let mut best_start = 0;

    for right in 0..s_bytes.len() {
        let c = s_bytes[right];
        *window.entry(c).or_insert(0) += 1;
        if let Some(&need_count) = need.get(&c) {
            if window[&c] == need_count {
                formed += 1;
            }
        }
        while formed == required {
            if right - left + 1 < best_len {
                best_len = right - left + 1;
                best_start = left;
            }
            let left_c = s_bytes[left];
            if let Some(&need_count) = need.get(&left_c) {
                if window[&left_c] == need_count {
                    formed -= 1;  // about to drop below the required count for this char
                }
            }
            *window.get_mut(&left_c).unwrap() -= 1;
            left += 1;
        }
    }

    if best_len == usize::MAX {
        String::new()
    } else {
        s[best_start..best_start + best_len].to_string()
    }
}

fn main() {
    assert_eq!(min_window("ADOBECODEBANC".to_string(), "ABC".to_string()), "BANC".to_string());
    assert_eq!(min_window("a".to_string(), "a".to_string()), "a".to_string());
    assert_eq!(min_window("a".to_string(), "aa".to_string()), "".to_string());  // t needs two 'a's, s only has one
    assert_eq!(min_window("ab".to_string(), "b".to_string()), "b".to_string());
    println!("minimum-window-substring: all assertions passed");
}
Complexity: O(n + m) time — each pointer moves forward at most n times total — O(m) space for the need/window maps (m = distinct chars in t).
Rust angle: The formed/required counters avoid recomputing "does the window currently satisfy t?" from scratch on every step, which would silently degrade this into O(n·|t|); the trick is comparing window[&c] == need_count at the exact moment a count crosses its threshold, not re-checking every key afterward. This solution operates on s.bytes()/Vec<u8> throughout rather than chars(), specifically so the final s[best_start..best_start + best_len] byte-range slice lines up correctly — mixing char-based indices with byte-based &str slicing here would either panic (splitting a multi-byte UTF-8 character) or silently return the wrong substring on non-ASCII input.

fn find_min(nums: Vec<i32>) -> i32 {
    let mut lo = 0usize;
    let mut hi = nums.len() - 1;
    while lo < hi {
        let mid = lo + (hi - lo) / 2;
        if nums[mid] > nums[hi] {
            lo = mid + 1;  // minimum is strictly to the right of mid
        } else {
            hi = mid;  // mid could itself be the minimum, so keep it in range
        }
    }
    nums[lo]
}

    let mut lo: i32 = 0;
    let mut hi: i32 = nums.len() as i32 - 1;
    while lo <= hi {
        let mid = lo + (hi - lo) / 2;
        let mv = nums[mid as usize];

            return mid;

        if nums[lo as usize] <= mv {

            if mv < target && target <= nums[hi as usize] {
                lo = mid + 1;
            } else {
                hi = mid - 1;
            }
        }
    }
    -1
}

#[derive(PartialEq, Eq, Clone, Debug)]
pub struct ListNode {
    pub val: i32,
    pub next: Option<Box<ListNode>>,
}
impl ListNode {
    #[inline]
    fn new(val: i32) -> Self {
        ListNode { val, next: None }
    }
}

fn reverse_list(head: Option<Box<ListNode>>) -> Option<Box<ListNode>> {
    let mut prev: Option<Box<ListNode>> = None;
    let mut curr = head;
    while let Some(mut node) = curr.take() {
        curr = node.next.take();  // detach the rest before we rewire this node
        node.next = prev;  // point this node backward
        prev = Some(node);  // it becomes the new front of the reversed prefix
    }
    prev
}

fn vec_to_list(v: Vec<i32>) -> Option<Box<ListNode>> {
    let mut head: Option<Box<ListNode>> = None;
    for &x in v.iter().rev() {
        let mut node = Box::new(ListNode::new(x));
        node.next = head;
        head = Some(node);
    }
    head
}

fn list_to_vec(mut head: Option<Box<ListNode>>) -> Vec<i32> {
    let mut out = Vec::new();
    while let Some(node) = head {
        out.push(node.val);
        head = node.next;
    }
    out
}

    assert_eq!(list_to_vec(reverse_list(vec_to_list(vec![1, 2, 3, 4, 5]))), vec![5, 4, 3, 2, 1]);

pub struct ListNode {
    pub val: i32,
    pub next: *mut ListNode,
}
impl ListNode {
    fn new(val: i32) -> Self {
        ListNode { val, next: ptr::null_mut() }
    }
}

fn has_cycle(head: *mut ListNode) -> bool {
    let mut slow = head;
    let mut fast = head;
    unsafe {
        while !fast.is_null() && !(*fast).next.is_null() {
            slow = (*slow).next;
            fast = (*(*fast).next).next;
            if slow == fast {
                return true;
            }
        }
    }
    false
}

fn main() {
    // Build [3,2,0,-4] with the tail wired back to index 1 (value 2) to form a real cycle.
    let mut nodes: Vec<Box<ListNode>> = vec![
        Box::new(ListNode::new(3)),
        Box::new(ListNode::new(2)),
        Box::new(ListNode::new(0)),
        Box::new(ListNode::new(-4)),
    ];
    let mut ptrs: Vec<*mut ListNode> = nodes.iter_mut().map(|n| n.as_mut() as *mut ListNode).collect();
    unsafe {
        (*ptrs[0]).next = ptrs[1];
        (*ptrs[1]).next = ptrs[2];
        (*ptrs[2]).next = ptrs[3];
        (*ptrs[3]).next = ptrs[1];  // tail points back into the middle of the list
    }
    assert!(has_cycle(ptrs[0]));

    // Build [1,2] with no cycle.
    let mut no_cycle: Vec<Box<ListNode>> = vec![Box::new(ListNode::new(1)), Box::new(ListNode::new(2))];
    let mut np: Vec<*mut ListNode> = no_cycle.iter_mut().map(|n| n.as_mut() as *mut ListNode).collect();
    unsafe {
        (*np[0]).next = np[1];
    }
    assert!(!has_cycle(np[0]));

    assert!(!has_cycle(ptr::null_mut()));  // edge: empty list

    let mut single = Box::new(ListNode::new(1));
    let sp = single.as_mut() as *mut ListNode;
    assert!(!has_cycle(sp));  // edge: single node, no cycle

    println!("linked-list-cycle: all assertions passed");
}

use std::cmp::Reverse;
use std::collections::BinaryHeap;

#[derive(PartialEq, Eq, Clone, Debug)]
pub struct ListNode {
    pub val: i32,
    pub next: Option<Box<ListNode>>,
}
impl ListNode {
    #[inline]
    fn new(val: i32) -> Self {
        ListNode { val, next: None }
    }
}

fn merge_k_lists(mut lists: Vec<Option<Box<ListNode>>>) -> Option<Box<ListNode>> {
    let mut heap: BinaryHeap<Reverse<(i32, usize)>> = BinaryHeap::new();
    for (i, node) in lists.iter().enumerate() {
        if let Some(n) = node {
            heap.push(Reverse((n.val, i)));  // Reverse turns the max-heap into a min-heap
        }
    }

    let mut dummy = Box::new(ListNode::new(0));
    let mut tail = &mut dummy;
    while let Some(Reverse((_, i))) = heap.pop() {
        let mut node = lists[i].take().unwrap();
        lists[i] = node.next.take();  // advance that list's own pointer
        if let Some(next) = &lists[i] {
            heap.push(Reverse((next.val, i)));  // re-seed the heap with the list's new front
        }
        tail.next = Some(node);
        tail = tail.next.as_mut().unwrap();
    }
    dummy.next
}

fn vec_to_list(v: Vec<i32>) -> Option<Box<ListNode>> {
    let mut head: Option<Box<ListNode>> = None;
    for &x in v.iter().rev() {
        let mut node = Box::new(ListNode::new(x));
        node.next = head;
        head = Some(node);
    }
    head
}

fn list_to_vec(mut head: Option<Box<ListNode>>) -> Vec<i32> {
    let mut out = Vec::new();
    while let Some(node) = head {
        out.push(node.val);
        head = node.next;
    }
    out
}

fn remove_nth_from_end(head: Option<Box<ListNode>>, n: i32) -> Option<Box<ListNode>> {
    fn helper(node: Option<Box<ListNode>>, n: i32, count: &mut i32) -> Option<Box<ListNode>> {
        match node {
            None => None,
            Some(mut boxed) => {
                boxed.next = helper(boxed.next.take(), n, count);  // recurse to the tail first
                *count += 1;  // then count back up from the end
                if *count == n {
                    boxed.next.take()  // this is the target: skip it by returning what comes after
                } else {
                    Some(boxed)
                }
            }
        }
    }

    let dummy = Box::new(ListNode { val: 0, next: head });  // dummy head handles "remove the real head" uniformly

    result.unwrap().next

Reorder List

Solution — reveal after attempting (O(n) time, O(1) space — find middle, reverse second half, merge alternately) 
#[derive(PartialEq, Eq, Clone, Debug)]
pub struct ListNode {
    pub val: i32,
    pub next: Option<Box<ListNode>>,
}
impl ListNode {
    #[inline]
    fn new(val: i32) -> Self {
        ListNode { val, next: None }
    }
}

fn reorder_list(head: &mut Option<Box<ListNode>>) {
    let mut len = 0;
    let mut cur = head.as_ref();
    while let Some(node) = cur {
        len += 1;
        cur = node.next.as_ref();
    }
    if len < 3 {
        return;  // 0, 1, or 2 nodes are already in reordered form
    }

    // split into first half [0..first_len) and second half [first_len..len)
    let first_len = (len + 1) / 2;
    let mut first_tail = head.as_mut().unwrap();
    for _ in 1..first_len {
        first_tail = first_tail.next.as_mut().unwrap();
    }
    let mut second = first_tail.next.take();

    // reverse the second half in place using the classic take() dance
    let mut prev: Option<Box<ListNode>> = None;
    while let Some(mut node) = second.take() {
        second = node.next.take();
        node.next = prev;
        prev = Some(node);
    }
    let mut second = prev;  // second half, reversed

    // merge the two halves alternately, moving a cursor through *head
    let mut remaining_first = head.take();
    let mut current = head;
    loop {
        let mut f = match remaining_first.take() {
            Some(node) => node,
            None => break,
        };
        remaining_first = f.next.take();
        *current = Some(f);
        current = &mut current.as_mut().unwrap().next;

        let mut s = match second.take() {
            Some(node) => node,
            None => break,
        };
        second = s.next.take();
        *current = Some(s);
        current = &mut current.as_mut().unwrap().next;
    }
}

fn vec_to_list(v: Vec<i32>) -> Option<Box<ListNode>> {
    let mut head: Option<Box<ListNode>> = None;
    for &x in v.iter().rev() {
        let mut node = Box::new(ListNode::new(x));
        node.next = head;
        head = Some(node);
    }
    head
}

        out.push(node.val);
        head = node.next;
    }
    out

fn main() {
    let mut l1 = vec_to_list(vec![1, 2, 3, 4]);
    reorder_list(&mut l1);
    assert_eq!(list_to_vec(l1), vec![1, 4, 2, 3]);

    let mut l2 = vec_to_list(vec![1, 2, 3, 4, 5]);
    reorder_list(&mut l2);
    assert_eq!(list_to_vec(l2), vec![1, 5, 2, 4, 3]);

    let mut l3 = vec_to_list(vec![1]);  // edge: single node, nothing to do
    reorder_list(&mut l3);
    assert_eq!(list_to_vec(l3), vec![1]);

    let mut l4: Option<Box<ListNode>> = None;  // edge: empty list
    reorder_list(&mut l4);
    assert_eq!(list_to_vec(l4), Vec::<i32>::new());

    println!("reorder-list: all assertions passed");
}
Complexity: O(n) time, O(1) auxiliary space (all three phases are linear scans/rewires, no extra allocation).
Rust angle: The merge phase needs a "cursor" that walks forward through *head while repeatedly attaching new nodes — the idiom is current = &mut current.as_mut().unwrap().next;, which reborrows through the just-written field and reassigns the cursor to point one node deeper, entirely in safe Rust. This only compiles because of non-lexical lifetimes: the old borrow of current is considered dead the instant it's used to produce the new value being assigned back into current. use std::cmp::Reverse;
use std::collections::BinaryHeap;

struct MedianFinder {
    lower: BinaryHeap<i32>,          // max-heap: top is the largest of the lower half
    upper: BinaryHeap<Reverse<i32>>,  // min-heap: top is the smallest of the upper half
}

impl MedianFinder {
    fn new() -> Self {
        MedianFinder { lower: BinaryHeap::new(), upper: BinaryHeap::new() }
    }

    fn add_num(&mut self, num: i32) {
        if self.lower.is_empty() || num <= *self.lower.peek().unwrap() {
            self.lower.push(num);
        } else {
            self.upper.push(Reverse(num));
        }

        // rebalance so the two heaps never differ in size by more than one
        if self.lower.len() > self.upper.len() + 1 {
            let moved = self.lower.pop().unwrap();
            self.upper.push(Reverse(moved));
        } else if self.upper.len() > self.lower.len() {
            let Reverse(moved) = self.upper.pop().unwrap();
            self.lower.push(moved);
        }
    }

    fn find_median(&self) -> f64 {
        if self.lower.len() > self.upper.len() {
            *self.lower.peek().unwrap() as f64
        } else {
            (*self.lower.peek().unwrap() as f64 + self.upper.peek().unwrap().0 as f64) / 2.0
        }
    }
}

fn main() {
    let mut mf = MedianFinder::new();
    mf.add_num(1);
    mf.add_num(2);
    assert_eq!(mf.find_median(), 1.5);  // [1,2] -> average of both

    mf.add_num(3);
    assert_eq!(mf.find_median(), 2.0);  // [1,2,3] -> middle element

    let mut mf2 = MedianFinder::new();
    mf2.add_num(5);
    assert_eq!(mf2.find_median(), 5.0);  // edge: single element

    let mut mf3 = MedianFinder::new();
    for n in [6, 2, 9, 1, 4, 8] {
        mf3.add_num(n);
    }
    assert_eq!(mf3.find_median(), 5.0);  // sorted [1,2,4,6,8,9] -> avg(4,6) == 5.0

    println!("find-median-data-stream: all assertions passed");
}
Complexity: O(log n) time per add_num (heap push/pop), O(1) time for find_median; O(n) space.
Rust angle: This needs both heap flavors at once, which is a great excuse to show you know BinaryHeap<T> is a max-heap by construction, and that BinaryHeap<Reverse<T>> is the idiomatic (and zero-cost — Reverse is a transparent tuple-struct wrapper) way to get min-heap behavior instead of writing a custom Ord impl. Destructuring straight out of the heap — let Reverse(moved) = self.upper.pop().unwrap(); — is a nice small idiom too: no separate .0 field access needed once you're already pattern-matching the Option. The other easy-to-miss detail is the rebalance order: checking lower.is_empty() before comparing num against *lower.peek().unwrap() is required, or the very first add_num call panics on unwrapping a None.

use std::cell::RefCell;

#[derive(Debug)]
pub struct TreeNode {

fn max_path_sum(root: Option<Rc<RefCell<TreeNode>>>) -> i32 {
    let mut best = i64::MIN;
    gain(&root, &mut best);
    best as i32
}

// Returns the best sum extendable upward through a single branch (this node
// plus at most one child), while updating `best` with the best "V-shaped"
// path (this node plus both children) seen anywhere in the tree.
fn gain(node: &Option<Rc<RefCell<TreeNode>>>, best: &mut i64) -> i64 {
    match node {
        None => 0,
        Some(n) => {
            let n = n.borrow();
            let left_gain = gain(&n.left, best).max(0);
            let right_gain = gain(&n.right, best).max(0);
            let through = n.val as i64 + left_gain + right_gain;
            if through > *best {
                *best = through;
            }
            n.val as i64 + left_gain.max(right_gain)
        }
    }
}

fn leaf(val: i32) -> Option<Rc<RefCell<TreeNode>>> {
    Some(Rc::new(RefCell::new(TreeNode::new(val))))
}

fn main() {

    let root = Some(Rc::new(RefCell::new(TreeNode { val: 1, left: leaf(2), right: leaf(3) })));
    assert_eq!(max_path_sum(root), 6);

    let n15 = leaf(15);
    let n7 = leaf(7);
    let n20 = Some(Rc::new(RefCell::new(TreeNode { val: 20, left: n15, right: n7 })));

use std::rc::Rc;
use std::cell::RefCell;
use std::collections::VecDeque;

#[derive(Debug)]
pub struct TreeNode {
    pub val: i32,
    pub left: Option<Rc<RefCell<TreeNode>>>,
    pub right: Option<Rc<RefCell<TreeNode>>>,
}
impl TreeNode {
    #[inline]
    pub fn new(val: i32) -> Self {
        TreeNode { val, left: None, right: None }
    }
}

fn level_order(root: Option<Rc<RefCell<TreeNode>>>) -> Vec<Vec<i32>> {
    let mut result = Vec::new();
    let mut queue: VecDeque<Rc<RefCell<TreeNode>>> = VecDeque::new();
    if let Some(node) = root {
        queue.push_back(node);
    }
    while !queue.is_empty() {
        let mut level = Vec::with_capacity(queue.len());
        for _ in 0..queue.len() {
            let node = queue.pop_front().unwrap();
            let n = node.borrow();
            level.push(n.val);
            if let Some(l) = &n.left {
                queue.push_back(Rc::clone(l));
            }
            if let Some(r) = &n.right {
                queue.push_back(Rc::clone(r));
            }
        }
        result.push(level);
    }
    result
}

fn leaf(val: i32) -> Option<Rc<RefCell<TreeNode>>> {
    Some(Rc::new(RefCell::new(TreeNode::new(val))))
}

fn main() {
    // empty tree
    assert_eq!(level_order(None), Vec::<Vec<i32>>::new());

    // single node
    assert_eq!(level_order(leaf(1)), vec![vec![1]]);

    // [3,9,20,null,null,15,7] -> [[3],[9,20],[15,7]]
    let n15 = leaf(15);
    let n7 = leaf(7);
    let n20 = Some(Rc::new(RefCell::new(TreeNode { val: 20, left: n15, right: n7 })));
    let n9 = leaf(9);
    let root = Some(Rc::new(RefCell::new(TreeNode { val: 3, left: n9, right: n20 })));
    assert_eq!(level_order(root), vec![vec![3], vec![9, 20], vec![15, 7]]);

    println!("level-order: all assertions passed");
}

Rust angle: VecDeque is the deliberate choice over Vec here — pop_front() on a Vec is O(n) because it has to shift every remaining element down, silently turning your "O(n) BFS" into O(n²). Capturing queue.len() before the inner for loop starts is what delimits exactly one level per outer iteration, since the loop body itself pushes new (next-level) entries onto the same queue as it drains the current ones. use std::cell::RefCell;
use std::collections::VecDeque;

#[derive(Debug)]

    pub val: i32,

struct Codec;

impl Codec {
    fn serialize(root: &Option<Rc<RefCell<TreeNode>>>) -> String {
        let mut out = String::new();
        Self::serialize_helper(root, &mut out);
        out
    }

    fn serialize_helper(node: &Option<Rc<RefCell<TreeNode>>>, out: &mut String) {
        match node {
            None => out.push_str("#,"),
            Some(n) => {
                let n = n.borrow();
                out.push_str(&n.val.to_string());
                out.push(',');
                Self::serialize_helper(&n.left, out);
                Self::serialize_helper(&n.right, out);
            }
        }
    }

    fn deserialize(data: String) -> Option<Rc<RefCell<TreeNode>>> {
        let mut tokens: VecDeque<&str> = data.split(',').filter(|s| !s.is_empty()).collect();
        Self::deserialize_helper(&mut tokens)
    }

    fn deserialize_helper(tokens: &mut VecDeque<&str>) -> Option<Rc<RefCell<TreeNode>>> {
        let token = tokens.pop_front().expect("unexpected end of token stream");
        if token == "#" {
            return None;
        }
        let val: i32 = token.parse().expect("malformed integer token");
        let left = Self::deserialize_helper(tokens);
        let right = Self::deserialize_helper(tokens);
        Some(Rc::new(RefCell::new(TreeNode { val, left, right })))
    }
}

use std::rc::Rc;
use std::cell::RefCell;
use std::collections::HashMap;

#[derive(Debug)]
pub struct TreeNode {
    pub val: i32,
    pub left: Option<Rc<RefCell<TreeNode>>>,
    pub right: Option<Rc<RefCell<TreeNode>>>,
}

    #[inline]
    pub fn new(val: i32) -> Self {

    }
}

fn build_tree(preorder: Vec<i32>, inorder: Vec<i32>) -> Option<Rc<RefCell<TreeNode>>> {
    let index_of_inorder: HashMap<i32, usize> =
        inorder.iter().enumerate().map(|(i, &v)| (v, i)).collect();
    let mut pre_pos = 0usize;
    build(&preorder, &mut pre_pos, &index_of_inorder, 0, inorder.len())
}

// Builds the subtree whose inorder values fall within `in_lo..in_hi`,
// consuming preorder values left-to-right via the shared cursor `pre_pos`.
fn build(
    preorder: &[i32],
    pre_pos: &mut usize,
    index_of_inorder: &HashMap<i32, usize>,
    in_lo: usize,
    in_hi: usize,
) -> Option<Rc<RefCell<TreeNode>>> {
    if in_lo >= in_hi {
        return None;
    }
    let root_val = preorder[*pre_pos];
    *pre_pos += 1;
    let mid = index_of_inorder[&root_val];
    let left = build(preorder, pre_pos, index_of_inorder, in_lo, mid);
    let right = build(preorder, pre_pos, index_of_inorder, mid + 1, in_hi);
    Some(Rc::new(RefCell::new(TreeNode { val: root_val, left, right })))
}

fn preorder_of(root: &Option<Rc<RefCell<TreeNode>>>, out: &mut Vec<i32>) {
    if let Some(node) = root {
        let n = node.borrow();
        out.push(n.val);
        preorder_of(&n.left, out);
        preorder_of(&n.right, out);
    }
}

fn inorder_of(root: &Option<Rc<RefCell<TreeNode>>>, out: &mut Vec<i32>) {
    if let Some(node) = root {
        let n = node.borrow();
        inorder_of(&n.left, out);
        out.push(n.val);
        inorder_of(&n.right, out);
    }
}

fn main() {
    // empty tree
    let empty = build_tree(vec![], vec![]);
    assert!(empty.is_none());

    // single node
    let single = build_tree(vec![1], vec![1]);
    let mut out = Vec::new();
    preorder_of(&single, &mut out);
    assert_eq!(out, vec![1]);

    // preorder = [3,9,20,15,7], inorder = [9,3,15,20,7]
    let tree = build_tree(vec![3, 9, 20, 15, 7], vec![9, 3, 15, 20, 7]);
    let mut pre_out = Vec::new();
    let mut in_out = Vec::new();
    preorder_of(&tree, &mut pre_out);
    inorder_of(&tree, &mut in_out);
    assert_eq!(pre_out, vec![3, 9, 20, 15, 7]);
    assert_eq!(in_out, vec![9, 3, 15, 20, 7]);

    println!("build-tree: all assertions passed");
}
Complexity: O(n) time with the HashMap lookup (vs. O(n²) if you linearly scan inorder for the split point each time), O(n) space for the map and recursion stack.
Rust angle: The trickiest part isn't ownership of the tree — it's that preorder must be consumed strictly left-to-right across the entire recursion, not just within one call's local slice, so pre_pos: &mut usize threaded through every recursive call (rather than each call computing its own index) is what keeps the cursor globally consistent. fn kth_smallest(root: Option<Rc<RefCell<TreeNode>>>, k: i32) -> i32 {
    let mut remaining = k;
    let mut answer = None;
    inorder(&root, &mut remaining, &mut answer);
    answer.expect("k was larger than the number of nodes in the tree")
}

// Inorder traversal of a BST visits values in ascending order, so we can
// stop the instant `remaining` hits zero instead of collecting everything.
fn inorder(node: &Option<Rc<RefCell<TreeNode>>>, remaining: &mut i32, answer: &mut Option<i32>) {
    if answer.is_some() {
        return;
    }
    if let Some(n) = node {
        let n = n.borrow();
        inorder(&n.left, remaining, answer);
        if answer.is_some() {
            return;
        }
        *remaining -= 1;
        if *remaining == 0 {
            *answer = Some(n.val);
            return;
        }
        inorder(&n.right, remaining, answer);
    }
}

fn leaf(val: i32) -> Option<Rc<RefCell<TreeNode>>> {
    Some(Rc::new(RefCell::new(TreeNode::new(val))))
}

    let n2 = leaf(2);
    let n1 = Some(Rc::new(RefCell::new(TreeNode { val: 1, left: None, right: n2 })));

use std::rc::Rc;
use std::cell::RefCell;

#[derive(Debug)]
pub struct TreeNode {
    pub val: i32,
    pub left: Option<Rc<RefCell<TreeNode>>>,
    pub right: Option<Rc<RefCell<TreeNode>>>,
}
impl TreeNode {
    #[inline]
    pub fn new(val: i32) -> Self {
        TreeNode { val, left: None, right: None }
    }
}

fn lowest_common_ancestor(
    root: Option<Rc<RefCell<TreeNode>>>,
    p: Rc<RefCell<TreeNode>>,
    q: Rc<RefCell<TreeNode>>,
) -> Option<Rc<RefCell<TreeNode>>> {
    let mut current = root;
    let (p_val, q_val) = (p.borrow().val, q.borrow().val);
    while let Some(node) = current.clone() {
        let n = node.borrow();
        if p_val < n.val && q_val < n.val {
            current = n.left.clone();
        } else if p_val > n.val && q_val > n.val {
            current = n.right.clone();
        } else {
            // p and q split here (or one equals this node) — this is the LCA.
            drop(n);
            return Some(node);
        }
    }
    None
}

fn leaf(val: i32) -> Option<Rc<RefCell<TreeNode>>> {
    Some(Rc::new(RefCell::new(TreeNode::new(val))))
}

fn main() {
    // BST: [6,2,8,0,4,7,9,null,null,3,5]
    let n3 = leaf(3);
    let n5 = leaf(5);
    let n4 = Rc::new(RefCell::new(TreeNode { val: 4, left: n3, right: n5 }));
    let n0 = leaf(0);
    let n2 = Rc::new(RefCell::new(TreeNode { val: 2, left: n0, right: Some(n4.clone()) }));
    let n7 = leaf(7);
    let n9 = leaf(9);
    let n8 = Rc::new(RefCell::new(TreeNode { val: 8, left: n7, right: n9 }));
    let root = Some(Rc::new(RefCell::new(TreeNode { val: 6, left: Some(n2.clone()), right: Some(n8.clone()) })));

    // p=2, q=8 -> split at root, LCA = 6
    let lca1 = lowest_common_ancestor(root.clone(), n2.clone(), n8.clone());
    assert_eq!(lca1.unwrap().borrow().val, 6);

    // p=2, q=4 -> 2 is an ancestor of 4, LCA = 2
    let lca2 = lowest_common_ancestor(root.clone(), n2.clone(), n4.clone());
    assert_eq!(lca2.unwrap().borrow().val, 2);

    // single-node tree, p == q == root -> LCA is the node itself
    let single = leaf(1).unwrap();
    let lca3 = lowest_common_ancestor(Some(single.clone()), single.clone(), single.clone());
    assert_eq!(lca3.unwrap().borrow().val, 1);

    // p=0, q=5 -> both under 2's subtree, LCA = 2
    let n0_ref = n2.borrow().left.clone().unwrap();
    let n5_ref = n4.borrow().right.clone().unwrap();
    let lca4 = lowest_common_ancestor(root, n0_ref, n5_ref);
    assert_eq!(lca4.unwrap().borrow().val, 2);

    println!("lca-bst: all assertions passed");
}
Complexity: O(h) time and O(1) extra space — an iterative walk down one path, no recursion stack and no visiting the "wrong" subtree at all.
Rust angle: Because BST ordering tells you which single direction to go, this is a nice contrast with LC 236's general-tree LCA — you don't need a recursive "search both children, see which one returns non-null" pattern at all, just an iterative while let Some(node) = current.clone() loop reassigning current. The one wrinkle: node.borrow() produces a Ref that borrows node, and you can't return Some(node) while that borrow is still alive (the borrow checker will flag it), so an explicit drop(n) right before the early return is the clean fix — an extra step you'd never need in a GC'd language where there's no live-borrow tracking to satisfy.

struct Trie {
    children: [Option<Box<Trie>>; 26],
    is_end: bool,
}

impl Trie {
    fn new() -> Self {
        Trie {
            children: Default::default(),
            is_end: false,
        }
    }

    fn insert(&mut self, word: String) {
        let mut node = self;
        for b in word.bytes() {
            let idx = (b - b'a') as usize;
            node = node.children[idx].get_or_insert_with(|| Box::new(Trie::new()));
        }
        node.is_end = true;
    }

    fn find(&self, word: &str) -> Option<&Trie> {
        let mut node = self;
        for b in word.bytes() {
            let idx = (b - b'a') as usize;
            match &node.children[idx] {
                Some(child) => node = child,
                None => return None,
            }
        }
        Some(node)
    }

    fn search(&self, word: String) -> bool {
        self.find(&word).map_or(false, |n| n.is_end)
    }

    fn starts_with(&self, prefix: String) -> bool {
        self.find(&prefix).is_some()
    }
}

fn main() {
    let mut trie = Trie::new();
    trie.insert("apple".to_string());
    assert!(trie.search("apple".to_string()));  // exact word inserted
    assert!(!trie.search("app".to_string()));  // prefix only, not inserted as a word
    assert!(trie.starts_with("app".to_string()));  // but it is a valid prefix
    trie.insert("app".to_string());
    assert!(trie.search("app".to_string()));  // now inserted as its own word
    assert!(!trie.starts_with("b".to_string()));  // edge case: no branch at all
    println!("implement-trie: all assertions passed");
}

Rust angle: [Option<Box<Trie>>; 26] is only legal because Box erases the recursive type's size behind a pointer — Trie containing Trie directly would be an infinitely-sized type and fail to compile. get_or_insert_with is the idiomatic one-liner for "descend, creating the node if it doesn't exist yet," replacing what would otherwise be an awkward two-branch match at every level.         Default::default()
    }

    fn add_word(&mut self, word: String) {
        let mut node = self;
        for b in word.bytes() {
            let idx = (b - b'a') as usize;
            node = node.children[idx].get_or_insert_with(|| Box::new(WordDictionary::new()));

    }

        Self::search_bytes(self, word.as_bytes())
    }

    // can't be resolved by a single deterministic lookup like a plain trie search can.
    fn search_bytes(node: &WordDictionary, word: &[u8]) -> bool {
        if word.is_empty() {
            return node.is_end;
        }
        let b = word[0];
        let rest = &word[1..];
        if b == b'.' {
            node.children
                .iter()
                .any(|child| child.as_ref().map_or(false, |c| Self::search_bytes(c, rest)))
        } else {
            let idx = (b - b'a') as usize;
            node.children[idx]
                .as_ref()
                .map_or(false, |c| Self::search_bytes(c, rest))
        }
    }
}

}

#[derive(Default)]
struct TrieNode {
    children: [Option<Box<TrieNode>>; 26],
    word: Option<String>,  // stores the full word at terminal nodes, avoids rebuilding strings during DFS
}

impl TrieNode {
    fn insert(&mut self, word: &str) {
        let mut node = self;
        for b in word.bytes() {
            let idx = (b - b'a') as usize;
            node = node.children[idx].get_or_insert_with(|| Box::new(TrieNode::default()));
        }
        node.word = Some(word.to_string());
    }
}

fn find_words(board: Vec<Vec<char>>, words: Vec<String>) -> Vec<String> {
    let mut root = TrieNode::default();
    for w in &words {
        root.insert(w);
    }

    let mut board = board;  // mutate in place for the visited marker, restore after backtracking
    let rows = board.len();
    let cols = if rows == 0 { 0 } else { board[0].len() };
    let mut found = Vec::new();

    for r in 0..rows {
        for c in 0..cols {
            dfs(&mut board, r, c, &mut root, &mut found);
        }
    }
    found
}

fn dfs(board: &mut Vec<Vec<char>>, r: usize, c: usize, node: &mut TrieNode, found: &mut Vec<String>) {
    let ch = board[r][c];
    if ch == '#' {
        return;  // already visited on this path
    }
    let idx = (ch as u8 - b'a') as usize;
    let child = match node.children[idx].as_mut() {
        Some(child) => child,
        None => return,  // pruned: no word in the trie continues with this letter
    };

    if let Some(w) = child.word.take() {
        found.push(w);  // take() clears it so the same word can't be reported twice
    }

    board[r][c] = '#';  // mark visited
    let rows = board.len() as i32;
    let cols = board[0].len() as i32;
    for (dr, dc) in [(-1, 0), (1, 0), (0, -1), (0, 1)] {
        let nr = r as i32 + dr;
        let nc = c as i32 + dc;
        if nr >= 0 && nr < rows && nc >= 0 && nc < cols {
            dfs(board, nr as usize, nc as usize, child, found);
        }
    }
    board[r][c] = ch;  // restore for other DFS paths
}

fn main() {
    let board = vec![
        vec!['o', 'a', 'a', 'n'],
        vec!['e', 't', 'a', 'e'],
        vec!['i', 'h', 'k', 'r'],
        vec!['i', 'f', 'l', 'v'],
    ];
    let words: Vec<String> = vec!["oath", "pea", "eat", "rain"]
        .into_iter()
        .map(String::from)
        .collect();
    let mut result = find_words(board, words);
    result.sort();
    assert_eq!(result, vec!["eat".to_string(), "oath".to_string()]);

    let board2 = vec![vec!['a', 'b'], vec!['c', 'd']];
    let words2: Vec<String> = vec!["abcb"].into_iter().map(String::from).collect();
    let result2 = find_words(board2, words2);
    assert!(result2.is_empty());  // 'abcb' would reuse 'b', not a valid path

    let board3 = vec![vec!['a']];
    let words3: Vec<String> = vec!["a"].into_iter().map(String::from).collect();
    assert_eq!(find_words(board3, words3), vec!["a".to_string()]);  // edge case: 1x1 board

    println!("word-search-ii: all assertions passed");
}

fn combination_sum(candidates: Vec<i32>, target: i32) -> Vec<Vec<i32>> {
    let mut candidates = candidates;
    candidates.sort();  // lets us prune early once remaining < 0 and skip re-checking earlier candidates
    let mut result = Vec::new();
    let mut path = Vec::new();
    backtrack(&candidates, target, 0, &mut path, &mut result);
    result
}

fn backtrack(
    candidates: &[i32],
    remaining: i32,
    start: usize,
    path: &mut Vec<i32>,
    result: &mut Vec<Vec<i32>>,
) {
    if remaining == 0 {
        result.push(path.clone());
        return;
    }
    for i in start..candidates.len() {
        if candidates[i] > remaining {
            break;  // sorted, so nothing further can work either
        }
        path.push(candidates[i]);
        backtrack(candidates, remaining - candidates[i], i, path, result);  // pass `i`, not `i + 1` — reuse allowed
        path.pop();
    }
}

fn main() {
    let mut r1 = combination_sum(vec![2, 3, 6, 7], 7);
    for c in r1.iter_mut() {
        c.sort();
    }
    r1.sort();
    assert_eq!(r1, vec![vec![2, 2, 3], vec![7]]);

    let mut r2 = combination_sum(vec![2, 3, 5], 8);
    for c in r2.iter_mut() {
        c.sort();
    }
    r2.sort();
    assert_eq!(r2, vec![vec![2, 2, 2, 2], vec![2, 3, 3], vec![3, 5]]);

    assert_eq!(combination_sum(vec![2], 1), Vec::<Vec<i32>>::new());  // edge case: no combination reaches target

    println!("combination-sum: all assertions passed");
}
Complexity: O(2^target) worst case in the number of recursive branches explored (bounded further by the candidate count), O(target/min(candidates)) recursion depth for the path buffer.
Rust angle: Passing i (not i + 1) as the next start is the whole trick for "unlimited reuse," and it's worth narrating out loud in an interview — it's easy to silently get this wrong and only notice via a failing test. path.push/path.pop around the recursive call is the idiomatic Rust backtracking shape: mutate a single owned Vec in place and undo the mutation on the way back up, rather than passing an ever-growing cloned Vec down each call (which would still be correct, just O(depth) extra allocations per branch). result.push(path.clone()) is the one clone that's actually necessary, since result needs to own an independent snapshot at the moment a valid combination is found.

    let word: Vec<char> = word.chars().collect();
    let rows = board.len();
    let cols = if rows == 0 { 0 } else { board[0].len() };

    for r in 0..rows {

            }
        }

fn backtrack(board: &mut Vec<Vec<char>>, r: usize, c: usize, word: &[char], idx: usize) -> bool {
    if board[r][c] != word[idx] {
        return false;
    }
    if idx == word.len() - 1 {
        return true;  // matched the last character, whole word found
    }

    let original = board[r][c];

use std::cell::RefCell;
use std::collections::HashMap;
use std::rc::Rc;

#[derive(Debug)]
struct Node {
    val: i32,
    neighbors: Vec<Rc<RefCell<Node>>>,
}

impl Node {
    fn new(val: i32) -> Self {
        Node { val, neighbors: Vec::new() }
    }
}

fn clone_graph(node: Option<Rc<RefCell<Node>>>) -> Option<Rc<RefCell<Node>>> {
    let mut visited: HashMap<i32, Rc<RefCell<Node>>> = HashMap::new();
    node.map(|n| dfs(&n, &mut visited))
}

// keyed by `val` (unique per node here) so a node already cloned on one path is reused,
// not recloned — this is what breaks infinite recursion on cycles.
fn dfs(node: &Rc<RefCell<Node>>, visited: &mut HashMap<i32, Rc<RefCell<Node>>>) -> Rc<RefCell<Node>> {
    let val = node.borrow().val;
    if let Some(clone) = visited.get(&val) {
        return Rc::clone(clone);
    }

    let clone = Rc::new(RefCell::new(Node::new(val)));
    visited.insert(val, Rc::clone(&clone));  // insert BEFORE recursing into neighbors, or a cycle recurses forever

    let neighbors: Vec<Rc<RefCell<Node>>> = node
        .borrow()
        .neighbors
        .iter()
        .map(|nbr| dfs(nbr, visited))
        .collect();
    clone.borrow_mut().neighbors = neighbors;
    clone
}

fn main() {
    // build a 4-cycle: 1-2-3-4-1
    let n1 = Rc::new(RefCell::new(Node::new(1)));
    let n2 = Rc::new(RefCell::new(Node::new(2)));
    let n3 = Rc::new(RefCell::new(Node::new(3)));
    let n4 = Rc::new(RefCell::new(Node::new(4)));
    n1.borrow_mut().neighbors = vec![Rc::clone(&n2), Rc::clone(&n4)];
    n2.borrow_mut().neighbors = vec![Rc::clone(&n1), Rc::clone(&n3)];
    n3.borrow_mut().neighbors = vec![Rc::clone(&n2), Rc::clone(&n4)];
    n4.borrow_mut().neighbors = vec![Rc::clone(&n1), Rc::clone(&n3)];

    let cloned = clone_graph(Some(Rc::clone(&n1))).unwrap();
    assert_eq!(cloned.borrow().val, 1);
    assert_eq!(cloned.borrow().neighbors.len(), 2);
    assert!(!Rc::ptr_eq(&cloned, &n1));  // must be a genuinely new node, not the same Rc

    // identity must be preserved: cloned n1's neighbor "2" and cloned n3's neighbor "2" are the same clone
    let cloned_n2_via_1 = Rc::clone(&cloned.borrow().neighbors[0]);  // n1.neighbors[0] == n2
    let cloned_n4_via_1 = Rc::clone(&cloned.borrow().neighbors[1]);  // n1.neighbors[1] == n4
    let cloned_n3_via_4 = Rc::clone(&cloned_n4_via_1.borrow().neighbors[1]);  // n4.neighbors[1] == n3

    assert!(clone_graph(None).is_none());  // edge case: empty graph

}

use std::collections::HashSet;

fn pacific_atlantic(heights: Vec<Vec<i32>>) -> Vec<Vec<i32>> {
    let rows = heights.len();
    let cols = if rows == 0 { 0 } else { heights[0].len() };
    if rows == 0 || cols == 0 {
        return Vec::new();
    }

    let mut pacific: HashSet<(usize, usize)> = HashSet::new();
    let mut atlantic: HashSet<(usize, usize)> = HashSet::new();

    // multi-source BFS/DFS starting FROM the ocean borders, flowing "uphill" (reverse of water
    // flow) into cells that are >= the current cell — this avoids O(rows*cols) individual
    // flow-checks from every single cell.
    for r in 0..rows {
        dfs(&heights, r, 0, &mut pacific);
        dfs(&heights, r, cols - 1, &mut atlantic);
    }
    for c in 0..cols {
        dfs(&heights, 0, c, &mut pacific);
        dfs(&heights, rows - 1, c, &mut atlantic);
    }

    let mut result = Vec::new();
    for r in 0..rows {
        for c in 0..cols {
            if pacific.contains(&(r, c)) && atlantic.contains(&(r, c)) {
                result.push(vec![r as i32, c as i32]);
            }
        }
    }
    result
}

fn dfs(heights: &[Vec<i32>], r: usize, c: usize, visited: &mut HashSet<(usize, usize)>) {
    if !visited.insert((r, c)) {
        return;  // already reached this cell from this ocean
    }
    let rows = heights.len() as i32;
    let cols = heights[0].len() as i32;
    for (dr, dc) in [(-1, 0), (1, 0), (0, -1), (0, 1)] {
        let nr = r as i32 + dr;
        let nc = c as i32 + dc;
        if nr >= 0 && nr < rows && nc >= 0 && nc < cols {
            let (nr, nc) = (nr as usize, nc as usize);
            if heights[nr][nc] >= heights[r][c] {
                dfs(heights, nr, nc, visited);
            }
        }
    }
}

fn main() {
    let heights = vec![
        vec![1, 2, 2, 3, 5],
        vec![3, 2, 3, 4, 4],
        vec![2, 4, 5, 3, 1],
        vec![6, 7, 1, 4, 5],
        vec![5, 1, 1, 2, 4],
    ];
    let mut result = pacific_atlantic(heights);
    result.sort();
    let mut expected = vec![
        vec![0, 4], vec![1, 3], vec![1, 4], vec![2, 2], vec![3, 0],
        vec![3, 1], vec![4, 0],

use std::collections::VecDeque;

fn can_finish(num_courses: i32, prerequisites: Vec<Vec<i32>>) -> bool {
    let n = num_courses as usize;
    let mut adj: Vec<Vec<usize>> = vec![Vec::new(); n];
    let mut in_degree = vec![0i32; n];

    for pair in &prerequisites {
        let (course, pre) = (pair[0] as usize, pair[1] as usize);
        adj[pre].push(course);
        in_degree[course] += 1;
    }

    // Kahn's algorithm: peel off nodes with no remaining prerequisites, layer by layer.
    // Iterative BFS with a queue sidesteps the borrow-checker friction a recursive DFS would
    // hit trying to share a mutable "visiting/visited" state array across call frames.
    let mut queue: VecDeque<usize> = (0..n).filter(|&i| in_degree[i] == 0).collect();
    let mut visited_count = 0;

    while let Some(course) = queue.pop_front() {
        visited_count += 1;
        for &next in &adj[course] {
            in_degree[next] -= 1;
            if in_degree[next] == 0 {
                queue.push_back(next);
            }
        }
    }

    visited_count == n  // if fewer than n courses were ever dequeued, a cycle blocked the rest
}

fn main() {
    assert!(can_finish(2, vec![vec![1, 0]]));  // 0 -> 1, simple chain
    assert!(!can_finish(2, vec![vec![1, 0], vec![0, 1]]));  // 0 -> 1 -> 0, a cycle
    assert!(can_finish(4, vec![vec![1, 0], vec![2, 0], vec![3, 1], vec![3, 2]]));  // diamond DAG
    assert!(can_finish(1, Vec::new()));  // edge case: no prerequisites at all

    println!("course-schedule: all assertions passed");
}
Complexity: O(V + E) time and space for building the adjacency list, in-degree array, and running the queue.
Rust angle: This is the canonical example of iterative BFS beating recursive DFS on borrow-checker ergonomics: a recursive cycle-detection DFS needs a "currently visiting" marker distinct from "fully visited" (to distinguish a back-edge cycle from a legitimately-shared diamond dependency), which means threading two mutable state arrays through recursive calls — annoying but not impossible in Rust, just more ceremony than Kahn's single pass. Building queue directly via (0..n).filter(...).collect() is a good idiomatic-iterator signal over manually pushing in a loop, and comparing visited_count == n at the end is a cheaper cycle check than trying to reconstruct which specific nodes never got visited.

struct UnionFind {
    parent: Vec<usize>,
    rank: Vec<u32>,
}

impl UnionFind {
    fn new(n: usize) -> Self {
        UnionFind { parent: (0..n).collect(), rank: vec![0; n] }
    }

    // path compression: every visited node is rewired straight to the root, flattening the tree
    // for future lookups — a compact, iterative way to keep find() nearly O(1) amortized.
    fn find(&mut self, x: usize) -> usize {
        if self.parent[x] != x {
            self.parent[x] = self.find(self.parent[x]);
        }
        self.parent[x]
    }

    // returns false if x and y were already connected (i.e. this edge would create a cycle)
    fn union(&mut self, x: usize, y: usize) -> bool {
        let (rx, ry) = (self.find(x), self.find(y));
        if rx == ry {
            return false;
        }
        // union by rank: attach the shorter tree under the taller one to keep depth low
        if self.rank[rx] < self.rank[ry] {
            self.parent[rx] = ry;
        } else if self.rank[rx] > self.rank[ry] {
            self.parent[ry] = rx;
        } else {
            self.parent[ry] = rx;
            self.rank[rx] += 1;
        }
        true
    }
}

fn valid_tree(n: i32, edges: Vec<Vec<i32>>) -> bool {
    let n = n as usize;
    if edges.len() != n - 1 {
        return false;  // a tree on n nodes has exactly n-1 edges, no more, no less
    }
    let mut uf = UnionFind::new(n);
    for edge in &edges {
        let (a, b) = (edge[0] as usize, edge[1] as usize);
        if !uf.union(a, b) {
            return false;  // this edge connects two already-connected nodes — a cycle
        }
    }
    true  // n-1 edges with no cycle detected means it's fully connected and acyclic
}

fn main() {
    assert!(valid_tree(5, vec![vec![0, 1], vec![0, 2], vec![0, 3], vec![1, 4]]));
    assert!(!valid_tree(5, vec![vec![0, 1], vec![1, 2], vec![2, 3], vec![1, 3], vec![1, 4]]));  // has a cycle
    assert!(!valid_tree(4, vec![vec![0, 1], vec![2, 3]]));  // right edge count but disconnected
    assert!(valid_tree(1, Vec::new()));  // edge case: single node, zero edges, still a valid (trivial) tree

    println!("graph-valid-tree: all assertions passed");
}

    parent: Vec<usize>,
    rank: Vec<u32>,
    count: i32,  // tracks component count incrementally instead of re-scanning parents at the end
}

impl UnionFind {
    fn new(n: usize) -> Self {
        UnionFind { parent: (0..n).collect(), rank: vec![0; n], count: n as i32 }
    }

    fn find(&mut self, x: usize) -> usize {

        self.parent[x]

    fn union(&mut self, x: usize, y: usize) {
        let (rx, ry) = (self.find(x), self.find(y));
        if rx == ry {
            return;  // already in the same component, no-op

        if self.rank[rx] < self.rank[ry] {
            self.parent[rx] = ry;

use std::collections::{BTreeSet, HashMap, HashSet, VecDeque};

fn alien_order(words: Vec<String>) -> String {
    let mut all_chars: BTreeSet<char> = BTreeSet::new();
    for w in &words {
        all_chars.extend(w.chars());
    }

    let mut adj: HashMap<char, HashSet<char>> = HashMap::new();
    let mut in_degree: HashMap<char, i32> = all_chars.iter().map(|&c| (c, 0)).collect();

    for pair in words.windows(2) {
        let (a, b) = (&pair[0], &pair[1]);
        let (ca, cb): (Vec<char>, Vec<char>) = (a.chars().collect(), b.chars().collect());
        let min_len = ca.len().min(cb.len());
        let mut found_diff = false;
        for i in 0..min_len {
            if ca[i] != cb[i] {
                if adj.entry(ca[i]).or_default().insert(cb[i]) {
                    *in_degree.entry(cb[i]).or_insert(0) += 1;
                }
                found_diff = true;
                break;
            }
        }
        // if "abc" comes before "ab" with no earlier difference, that's an invalid ordering —
        // a valid dictionary can never have a longer word be a strict prefix predecessor
        if !found_diff && ca.len() > cb.len() {
            return String::new();
        }
    }

    // Kahn's algorithm; BTreeSet keeps the frontier ordered so the result is deterministic
    // rather than depending on HashMap iteration order.
    let mut queue: VecDeque<char> = all_chars
        .iter()
        .copied()
        .filter(|c| in_degree[c] == 0)
        .collect();
    let mut order = String::new();

    while let Some(c) = queue.pop_front() {
        order.push(c);
        if let Some(neighbors) = adj.get(&c) {
            let mut next_ready: Vec<char> = Vec::new();
            for &n in neighbors {
                let deg = in_degree.get_mut(&n).unwrap();
                *deg -= 1;
                if *deg == 0 {
                    next_ready.push(n);
                }
            }
            next_ready.sort();  // stable tie-break so repeated runs give the same output
            for n in next_ready {
                queue.push_back(n);
            }
        }
    }

    if order.len() != all_chars.len() {
        String::new()  // fewer chars emitted than exist means a cycle blocked the rest
    } else {
        order
    }
}

fn main() {
    assert_eq!(alien_order(vec!["wrt".into(), "wrf".into(), "er".into(), "ett".into(), "rftt".into()]), "wertf");
    assert_eq!(alien_order(vec!["z".into(), "x".into()]), "zx");
    assert_eq!(alien_order(vec!["z".into(), "x".into(), "z".into()]), "");  // cycle: z -> x -> z
    assert_eq!(alien_order(vec!["abc".into(), "ab".into()]), "");  // invalid: longer word precedes its own prefix
    assert_eq!(alien_order(vec!["abc".into()]), "abc");  // edge case: single word, no constraints derived, sorted by first-seen order

    println!("alien-dictionary: all assertions passed");
}
Complexity: O(C) time where C is the total length of all words (building constraints), plus O(V + E) for the topological sort over the alphabet subset actually used.
Rust angle: The two failure modes are easy to conflate but need separate handling in the code: the prefix-order check ("abc" before "ab") is detected structurally while scanning word pairs, before any graph algorithm runs, while a genuine cycle (z → x → z) can only be detected after Kahn's algorithm finishes by comparing order.len() against the full alphabet size — conflating the two into one check is the most common bug on this problem. Using adj.entry(ca[i]).or_default().insert(cb[i]) returning bool to gate the in_degree increment prevents double-counting the same edge if two different word pairs happen to imply the same character constraint. Seeding the initial queue from a BTreeSet (rather than iterating a HashMap) and sorting each newly-freed batch of nodes before enqueueing them is what makes the output deterministic across runs — without it, any topologically valid ordering would be equally "correct" but the test assertions would be flaky.

fn length_of_lis(nums: Vec<i32>) -> i32 {
    let mut tails: Vec<i32> = Vec::new();
    for n in nums {
        match tails.binary_search(&n) {
            Ok(_) => {}  // n already a tail value; length unchanged
            Err(pos) => {
                if pos == tails.len() {
                    tails.push(n);  // n extends the longest subsequence so far
                } else {
                    tails[pos] = n;  // n gives a smaller tail for this length
                }
            }
        }
    }
    tails.len() as i32
}

}

fn coin_change(coins: Vec<i32>, amount: i32) -> i32 {
    let amount = amount as usize;
    let mut dp = vec![i32::MAX; amount + 1];
    dp[0] = 0;
    for a in 1..=amount {
        for &c in &coins {
            let c = c as usize;
            if c <= a && dp[a - c] != i32::MAX {
                dp[a] = dp[a].min(dp[a - c] + 1);

    } else {
        dp[amount]
    }
}

fn num_decodings(s: String) -> i32 {
    let bytes = s.as_bytes();
    let n = bytes.len();
    if n == 0 || bytes[0] == b'0' {
        return 0;
    }
    let mut dp = vec![0i32; n + 1];
    dp[0] = 1;  // empty prefix: exactly one way to decode nothing
    dp[1] = 1;  // first char is non-zero, checked above
    for i in 2..=n {
        if bytes[i - 1] != b'0' {
            dp[i] += dp[i - 1];  // decode s[i-1] as its own single-digit letter
        }
        let two: i32 = s[i - 2..i].parse().unwrap();
        if (10..=26).contains(&two) {
            dp[i] += dp[i - 2];  // decode s[i-2..i] as a two-digit letter
        }
    }
    dp[n]
}

    assert_eq!(num_decodings("10".to_string()), 1);
    assert_eq!(num_decodings("0".to_string()), 0);
    println!("decode-ways: all assertions passed");
}

Signature

fn longest_palindrome(s: String) -> String {
    let chars: Vec<char> = s.chars().collect();
    if chars.is_empty() {
        return String::new();
    }
    let mut best_l = 0;
    let mut best_r = 0;

    fn expand(chars: &[char], mut l: i32, mut r: i32) -> (usize, usize) {
        while l >= 0 && (r as usize) < chars.len() && chars[l as usize] == chars[r as usize] {
            l -= 1;
            r += 1;
        }
        // last valid window is (l+1 .. r-1)
        ((l + 1) as usize, (r - 1) as usize)
    }

    for i in 0..chars.len() {
        let (l1, r1) = expand(&chars, i as i32, i as i32); // odd length
        if r1 - l1 > best_r - best_l {
            best_l = l1;
            best_r = r1;
        }
        let (l2, r2) = expand(&chars, i as i32, i as i32 + 1); // even length
        if r2 >= l2 && r2 - l2 > best_r - best_l {
            best_l = l2;
            best_r = r2;
        }
    }
    chars[best_l..=best_r].iter().collect()
}

fn main() {
    let a = longest_palindrome("babad".into());
    assert!(a == "bab" || a == "aba");
    assert_eq!(longest_palindrome("cbbd".into()), "bb");
    assert_eq!(longest_palindrome("a".into()), "a");
    assert_eq!(longest_palindrome("ac".into()), "a");
    println!("longest-palindromic-substring: all assertions passed");
}
Complexity: O(n²) time, O(n) space for the char buffer (expand-around-center; Manacher's is O(n) but overkill for interviews).

Example: text1 = "abcde", text2 = "ace" → 3 ("ace").

Solution — reveal after attempting (classic O(n×m) 2-D table) 
fn longest_common_subsequence(text1: String, text2: String) -> i32 {
    let a = text1.as_bytes();
    let b = text2.as_bytes();
    let (n, m) = (a.len(), b.len());
    let mut dp = vec![vec![0i32; m + 1]; n + 1];
    for i in 1..=n {
        for j in 1..=m {
            if a[i - 1] == b[j - 1] {
                dp[i][j] = dp[i - 1][j - 1] + 1;
            } else {
                dp[i][j] = dp[i - 1][j].max(dp[i][j - 1]);
            }
        }
    }
    dp[n][m]
}

fn main() {
    assert_eq!(
        longest_common_subsequence("abcde".to_string(), "ace".to_string()),
        3
    );
    assert_eq!(
        longest_common_subsequence("abc".to_string(), "abc".to_string()),
        3
    );
    assert_eq!(
        longest_common_subsequence("abc".to_string(), "def".to_string()),
        0
    );
    assert_eq!(
        longest_common_subsequence("".to_string(), "abc".to_string()),
        0
    );
    println!("longest-common-subsequence: all assertions passed");
}
Complexity: O(n × m) time, O(n × m) space.
Rust angle: Rust Strings don't support s[i] to grab the i-th character — they're UTF-8, so integer indexing would be ambiguous between "byte offset" and "character offset," and the standard library simply doesn't implement Index<usize> for String at all (it's a compile error, not a runtime one). .as_bytes() sidesteps this by handing you a &[u8] with real O(1) integer indexing, which is exactly what this table needs and is safe here because the problem guarantees lowercase ASCII input (one byte per character); for genuinely Unicode-aware LCS you'd collect into a Vec<char> first instead.

fn max_sub_array(nums: Vec<i32>) -> i32 {
    let mut best = nums[0];

    for &n in &nums[1..] {

    best

Jump Game
Given an array nums where nums[i] is the maximum jump length from index i, starting at index 0, return true if you can reach the last index.

Example: nums = [2, 3, 1, 1, 4] → true (jump 1 step to index 1, then 3 steps to the last index).

Solution — reveal after attempting (O(n) greedy furthest-reach, single pass) 
fn can_jump(nums: Vec<i32>) -> bool {
    let mut reach = 0usize;
    for (i, &n) in nums.iter().enumerate() {
        if i > reach {
            return false;  // this index is unreachable from anything before it
        }
        reach = reach.max(i + n as usize);
    }
    true
}

fn main() {
    assert!(can_jump(vec![2, 3, 1, 1, 4]));
    assert!(!can_jump(vec![3, 2, 1, 0, 4]));
    assert!(can_jump(vec![0]));
    assert!(!can_jump(vec![0, 1]));
    println!("jump-game: all assertions passed");
}
Complexity: O(n) time, O(1) space — no DP table needed at all.
Rust angle: i + n as usize mixes the loop index (naturally usize) with nums[i] (an i32, since that's LeetCode's declared element type) — the as usize cast is required just to make the addition type-check, and it's a silently truncating/reinterpreting cast that would produce a huge nonsensical usize if n were ever negative (the problem's constraints rule that out, but the compiler won't stop you from writing this cast on a problem where it couldn't). This is also a clean illustration of greedy fully replacing DP: the natural first instinct is a Vec<bool> reachability table, but tracking one reach: usize scalar and bailing out the moment i > reach gets the same answer in a single pass with zero extra memory.

Solution — reveal after attempting (O(n) single pass, three phases) 
fn insert(intervals: Vec<Vec<i32>>, mut new_interval: Vec<i32>) -> Vec<Vec<i32>> {
    let mut result: Vec<Vec<i32>> = Vec::new();
    let n = intervals.len();
    let mut i = 0;

    // phase 1: intervals that end entirely before the new one starts
    while i < n && intervals[i][1] < new_interval[0] {
        result.push(intervals[i].clone());
        i += 1;
    }

    // phase 2: absorb every interval that overlaps new_interval into it
    while i < n && intervals[i][0] <= new_interval[1] {
        new_interval[0] = new_interval[0].min(intervals[i][0]);
        new_interval[1] = new_interval[1].max(intervals[i][1]);
        i += 1;
    }
    result.push(new_interval);

    // phase 3: everything left starts after the merged interval ends
    while i < n {
        result.push(intervals[i].clone());
        i += 1;
    }

    result
}

fn main() {
    assert_eq!(
        insert(vec![vec![1, 3], vec![6, 9]], vec![2, 5]),
        vec![vec![1, 5], vec![6, 9]]
    );
    assert_eq!(
        insert(vec![vec![1, 2], vec![3, 5], vec![6, 7], vec![8, 10], vec![12, 16]], vec![4, 8]),
        vec![vec![1, 2], vec![3, 10], vec![12, 16]]
    );
    assert_eq!(insert(vec![], vec![5, 7]), vec![vec![5, 7]]);  // edge: empty interval list
    assert_eq!(
        insert(vec![vec![1, 5]], vec![6, 8]),
        vec![vec![1, 5], vec![6, 8]]
    );  // edge: new interval doesn't overlap anything, goes at the end
    println!("insert-interval: all assertions passed");
}
Complexity: O(n) time, O(n) space — one linear pass split into three phases (before, overlapping, after).
Rust angle: Taking new_interval by value and marking it mut in the signature lets you grow it in place across phase 2 without a separate mutable local — a small but idiomatic signal that you understand Rust lets you shadow-mutate an owned parameter instead of reassigning through a fresh let mut. Note also that intervals[i].clone() is required in phases 1 and 3: you're building a brand-new Vec<Vec<i32>> result while only holding a shared reference into the input via indexing, so the compiler forces you to either clone each inner Vec<i32> or consume intervals with into_iter() — there's no way to "just point at" the old slices the way you might slice-copy references in C++.

Merge Intervals
Given a collection of intervals in no particular order, merge all overlapping ones and return the smallest set of intervals that covers exactly the same ranges.

Solution — reveal after attempting (O(n log n) sort by start, then sweep) 
fn merge(mut intervals: Vec<Vec<i32>>) -> Vec<Vec<i32>> {
    intervals.sort_by_key(|iv| iv[0]);  // sort by start
    let mut result: Vec<Vec<i32>> = Vec::new();
    for interval in intervals {
        if let Some(last) = result.last_mut() {
            if interval[0] <= last[1] {
                last[1] = last[1].max(interval[1]);  // overlaps — extend the last merged interval
                continue;
            }
        }
        result.push(interval);  // no overlap (or result empty) — start a new run
    }
    result
}

fn main() {
    assert_eq!(
        merge(vec![vec![1, 3], vec![2, 6], vec![8, 10], vec![15, 18]]),
        vec![vec![1, 6], vec![8, 10], vec![15, 18]]
    );
    assert_eq!(merge(vec![vec![1, 4], vec![4, 5]]), vec![vec![1, 5]]);  // touching endpoints still merge
    assert_eq!(merge(vec![vec![1, 4]]), vec![vec![1, 4]]);  // edge: single interval, nothing to merge
    assert_eq!(merge(vec![vec![1, 4], vec![0, 4]]), vec![vec![0, 4]]);  // unsorted input, must sort first
    println!("merge-intervals: all assertions passed");
}
Complexity: O(n log n) time (dominated by the sort), O(n) space for the result.
Rust angle: result.last_mut() returning Option<&mut Vec<i32>> is the idiomatic way to "peek and possibly mutate the last pushed element" without index-based bounds checking or an off-by-one on result.len() - 1. The if let without an else is a deliberate control-flow trick: when it matches and overlaps, continue skips the loop tail; when it doesn't match (or the condition inside is false), execution just falls through to result.push(interval) below — no need for a boolean flag to track "did we merge".

fn erase_overlap_intervals(mut intervals: Vec<Vec<i32>>) -> i32 {
    if intervals.is_empty() {
        return 0;
    }
    intervals.sort_by_key(|iv| iv[1]);  // sort by END — the greedy trick that makes this work
    let mut count = 0;  // number of intervals removed so far
    let mut prev_end = intervals[0][1];
    for interval in intervals.iter().skip(1) {
        if interval[0] < prev_end {
            count += 1;  // overlaps the kept interval — greedily drop this one, it ends later
        } else {
            prev_end = interval[1];  // keep it, it becomes the new reference end
        }
    }
    count
}

fn main() {
    assert_eq!(erase_overlap_intervals(vec![vec![1, 2], vec![2, 3], vec![3, 4], vec![1, 3]]), 1);
    assert_eq!(erase_overlap_intervals(vec![vec![1, 2], vec![1, 2], vec![1, 2]]), 2);  // three identical intervals, keep only one
    assert_eq!(erase_overlap_intervals(vec![vec![1, 2], vec![2, 3]]), 0);  // touching endpoints, nothing to remove
    assert_eq!(erase_overlap_intervals(vec![]), 0);  // edge: empty input
    println!("non-overlapping-intervals: all assertions passed");
}
Complexity: O(n log n) time for the sort, O(1) extra space beyond the sort itself (a single running counter and prev_end).
Rust angle: The early if intervals.is_empty() { return 0; } guard isn't just style — intervals[0][1] right after would panic with an index-out-of-bounds if it ran on an empty Vec, and Rust has no silent "return default/None" behavior for out-of-range indexing the way some languages' array access might. Sorting by end instead of start is the actual algorithmic insight (unrelated to Rust), but implementing it is identical either way thanks to sort_by_key(|iv| iv[1]) — swapping the greedy strategy is a one-character diff (iv[0] → iv[1]), which is worth calling out loud in an interview.

Given a list of meeting time intervals, find the minimum number of conference rooms required so that every meeting can happen, possibly overlapping in time with others in a different room.

Solution — reveal after attempting (O(n log n) sort by start + min-heap of end times) 
use std::cmp::Reverse;
use std::collections::BinaryHeap;

fn min_meeting_rooms(mut intervals: Vec<Vec<i32>>) -> i32 {
    intervals.sort_by_key(|iv| iv[0]);
    let mut end_times: BinaryHeap<Reverse<i32>> = BinaryHeap::new();  // min-heap via Reverse
    for interval in intervals {
        if let Some(&Reverse(earliest_end)) = end_times.peek() {
            if earliest_end <= interval[0] {
                end_times.pop();  // that room freed up in time — reuse it
            }
        }
        end_times.push(Reverse(interval[1]));  // either way, this meeting now occupies a room
    }
    end_times.len() as i32
}

fn main() {
    assert_eq!(min_meeting_rooms(vec![vec![0, 30], vec![5, 10], vec![15, 20]]), 2);
    assert_eq!(min_meeting_rooms(vec![vec![7, 10], vec![2, 4]]), 1);
    assert_eq!(min_meeting_rooms(vec![]), 0);  // edge: no meetings
    assert_eq!(min_meeting_rooms(vec![vec![1, 5], vec![5, 10], vec![10, 15]]), 1);  // back-to-back, one room suffices
    println!("meeting-rooms-ii: all assertions passed");
}
Complexity: O(n log n) time (sort plus n heap operations, each O(log n)), O(n) space for the heap.
Rust angle: std::collections::BinaryHeap is a max-heap with no built-in min-heap counterpart, so the standard trick is wrapping every element in std::cmp::Reverse, which inverts its Ord implementation — this is the single most common heap idiom you'll reach for across the whole Blind 75 set. fn rotate(matrix: &mut Vec<Vec<i32>>) {
    let n = matrix.len();
    // transpose: swap matrix[i][j] with matrix[j][i] across the diagonal
    for i in 0..n {
        for j in (i + 1)..n {
            let tmp = matrix[i][j];
            matrix[i][j] = matrix[j][i];
            matrix[j][i] = tmp;
        }
    }
    // reverse each row — transpose + row-reverse == 90° clockwise rotation
    for row in matrix.iter_mut() {
        row.reverse();
    }
}

fn spiral_order(matrix: Vec<Vec<i32>>) -> Vec<i32> {
    if matrix.is_empty() || matrix[0].is_empty() {
        return vec![];
    }
    let mut result = Vec::new();
    // signed bounds — avoids usize underflow when shrinking right/bottom past zero
    let (mut top, mut bottom) = (0_i32, matrix.len() as i32 - 1);
    let (mut left, mut right) = (0_i32, matrix[0].len() as i32 - 1);

    while top <= bottom && left <= right {
        for col in left..=right {
            result.push(matrix[top as usize][col as usize]);  // across the top row
        }
        top += 1;

        for row in top..=bottom {
            result.push(matrix[row as usize][right as usize]);  // down the right column
        }
        right -= 1;

        if top <= bottom {
            for col in (left..=right).rev() {
                result.push(matrix[bottom as usize][col as usize]);  // back across the bottom row
            }
            bottom -= 1;
        }

        if left <= right {
            for row in (top..=bottom).rev() {
                result.push(matrix[row as usize][left as usize]);  // back up the left column
            }
            left += 1;
        }
    }
    result
}

fn main() {
    assert_eq!(
        spiral_order(vec![vec![1, 2, 3], vec![4, 5, 6], vec![7, 8, 9]]),
        vec![1, 2, 3, 6, 9, 8, 7, 4, 5]
    );
    assert_eq!(
        spiral_order(vec![vec![1, 2, 3, 4], vec![5, 6, 7, 8], vec![9, 10, 11, 12]]),
        vec![1, 2, 3, 4, 8, 12, 11, 10, 9, 5, 6, 7]
    );
    assert_eq!(spiral_order(vec![vec![1]]), vec![1]);  // edge: single element
    assert_eq!(spiral_order(vec![vec![1, 2, 3]]), vec![1, 2, 3]);  // edge: single row
    println!("spiral-matrix: all assertions passed");
}
Complexity: O(m·n) time — every cell is visited exactly once, O(m·n) space for the output vector (O(1) beyond it).
Rust angle: This is the clearest example in the category of why usize's unsigned-ness actively fights you: a single-row matrix drives bottom to 0 immediately, and the very next ring's boundary math wants to go to -1 — if top/bottom/left/right were declared as usize, that -1 would either panic ("attempt to subtract with overflow") in debug builds or wrap to usize::MAX in release, silently corrupting every subsequent loop bound. Declaring them i32 and only casting to usize at the point of indexing (top as usize) sidesteps the whole class of bug, at the cost of remembering the cast at every single array access.

fn set_zeroes(matrix: &mut Vec<Vec<i32>>) {
    let rows = matrix.len();
    let cols = matrix[0].len();
    let mut first_row_has_zero = false;
    let mut first_col_has_zero = false;

    // record separately whether row 0 / col 0 themselves need zeroing,
    // since we're about to repurpose them as markers
    for r in 0..rows {
        if matrix[r][0] == 0 {
            first_col_has_zero = true;
        }
    }
    for c in 0..cols {
        if matrix[0][c] == 0 {
            first_row_has_zero = true;
        }
    }

    // use row 0 / col 0 as markers for the rest of the matrix
    for r in 1..rows {
        for c in 1..cols {
            if matrix[r][c] == 0 {
                matrix[r][0] = 0;
                matrix[0][c] = 0;
            }
        }
    }

    // zero out cells whose row-marker or col-marker got set
    for r in 1..rows {
        for c in 1..cols {
            if matrix[r][0] == 0 || matrix[0][c] == 0 {
                matrix[r][c] = 0;
            }
        }
    }

    if first_row_has_zero {
        for c in 0..cols {
            matrix[0][c] = 0;
        }
    }
    if first_col_has_zero {
        for r in 0..rows {
            matrix[r][0] = 0;
        }
    }
}

fn main() {
    let mut m1 = vec![vec![1, 1, 1], vec![1, 0, 1], vec![1, 1, 1]];
    set_zeroes(&mut m1);
    assert_eq!(m1, vec![vec![1, 0, 1], vec![0, 0, 0], vec![1, 0, 1]]);

    let mut m2 = vec![vec![0, 1, 2, 0], vec![3, 4, 5, 2], vec![1, 3, 1, 5]];
    set_zeroes(&mut m2);
    assert_eq!(
        m2,
        vec![vec![0, 0, 0, 0], vec![0, 4, 5, 0], vec![0, 3, 1, 0]]
    );

    let mut m3 = vec![vec![1]];  // edge: 1x1, no zero present
    set_zeroes(&mut m3);
    assert_eq!(m3, vec![vec![1]]);

    let mut m4 = vec![vec![0]];  // edge: 1x1, the only cell is itself zero
    set_zeroes(&mut m4);
    assert_eq!(m4, vec![vec![0]]);

    println!("set-matrix-zeroes: all assertions passed");
}
Complexity: O(m·n) time (a small constant number of full passes), O(1) extra space — row 0 and column 0 double as the marker storage instead of a separate HashSet.
Rust angle: This one is a good showcase of Rust forcing you to think about aliasing up front: because matrix[r][c], matrix[r][0], and matrix[0][c] are all separate indexing expressions into the same &mut Vec<Vec<i32>>, you can freely read one and write another in the same statement (each index expression's borrow ends immediately), but you could never hold two of them as live &mut references simultaneously — which is exactly why the "use row 0 / col 0 as in-place markers" trick reads naturally in Rust: it's structured as sequential read-then-write on scalar i32 elements, never as two overlapping mutable borrows.

Sum of Two Integers
Given two integers a and b, return their sum without using the + or - operators. The intended approach simulates binary addition: XOR gives the "sum without carry" and AND-then-shift-left gives the carry, repeated until there's no carry left.

Example: a = -2, b = 3 → 1 (same result + would give, just computed bit by bit).
Signature
fn get_sum(a: i32, b: i32) -> i32 { /* ... */ }
Solution — reveal after attempting (loop: XOR for sum, AND+shift for carry, until carry is 0) 
fn get_sum(a: i32, b: i32) -> i32 {
    // reinterpret the bit pattern as u32 so the carry loop works with plain,
    // unsigned bitwise ops instead of leaning on i32's sign-bit behavior
    let (mut a, mut b) = (a as u32, b as u32);
    while b != 0 {
        let carry = (a & b) << 1;  // bits that need to carry over
        a ^= b;                   // sum without carry
        b = carry;
    }
    a as i32  // cast back — the two's complement bit pattern round-trips exactly
}

fn main() {
    assert_eq!(get_sum(1, 2), 3);
    assert_eq!(get_sum(-2, 3), 1);  // negative operand
    assert_eq!(get_sum(i32::MIN, i32::MAX), -1);  // full-width carry chain across both extremes, still fits in i32
    assert_eq!(get_sum(-5, -7), -12);  // both negative
    println!("sum-of-two-integers: all assertions passed");
}
Complexity: O(1) time and space for 32-bit integers — the carry loop runs at most 32 times, since each iteration either terminates or shifts the carry one bit further left.
Rust angle: The whole premise of "no +/-" collides head-on with a real Rust footgun: debug builds panic on integer overflow with attempt to add with overflow, so even the "obvious cheat" of just writing a + b would blow up on inputs like i32::MAX + 1 — behavior Python (arbitrary precision) and Java/C++ (silent wraparound) don't share. This solution sidesteps that entirely since ^, &, and << are pure bitwise ops that Rust never overflow-checks, but casting through u32 first keeps the carry math honestly unsigned instead of relying on how i32's sign bit happens to behave under shifts. It's also worth naming the actual one-line "cheat" for a follow-up: a.wrapping_add(b) is the idiomatic way to add two integers in Rust when you explicitly want 32-bit wraparound instead of a panic — precisely the semantics this hand-rolled loop is reproducing bit by bit.

Number of 1 Bits
Given an unsigned 32-bit integer, return the number of set bits it has (its "population count" / Hamming weight).

Example: n = 0b1011 → 3 (three bits are set).
Signature
fn hamming_weight(n: u32) -> i32 { /* ... */ }
Solution — reveal after attempting (O(k) where k = number of set bits, via Brian Kernighan's trick) 
fn hamming_weight(mut n: u32) -> i32 {
    let mut count = 0;
    while n != 0 {
        n &= n - 1;  // clears the lowest set bit each iteration
        count += 1;
    }
    count
}

fn main() {
    assert_eq!(hamming_weight(0b00000000000000000000000000001011), 3);
    assert_eq!(hamming_weight(0b00000000000000000000000010000000), 1);
    assert_eq!(hamming_weight(0), 0);  // edge: zero has no set bits
    assert_eq!(hamming_weight(u32::MAX), 32);  // edge: all 32 bits set
    assert_eq!(hamming_weight(u32::MAX), u32::MAX.count_ones() as i32);  // idiomatic one-liner agrees with the manual loop
    println!("number-of-1-bits: all assertions passed");
}
Complexity: O(k) time where k is the number of set bits (at most 32 iterations), O(1) space.
Rust angle: n &= n - 1 only ever runs while the loop guard n != 0 holds, which matters specifically in Rust: n - 1 on a u32 is a checked subtraction in debug builds, and 0u32 - 1 would panic with attempt to subtract with overflow — the loop condition is what keeps this solution safe, not luck. That said, the real idiomatic answer here is n.count_ones(): the standard library ships population-count as a single intrinsic-backed method, and reaching for it directly (while still knowing the manual bit-trick for when an interviewer says "now implement it yourself") is exactly the signal worth showing.

Counting Bits
Given a non-negative integer n, return a vector where the value at index i (for every i from 0 to n) is the number of set bits in i.

Example: n = 5 → [0, 1, 1, 2, 1, 2] (e.g. 3 = 0b11 has 2 set bits, so index 3 holds 2).
Signature
fn count_bits(n: i32) -> Vec<i32> { /* ... */ }
Solution — reveal after attempting (O(n) DP: dp[i] = dp[i >> 1] + (i & 1)) 
fn count_bits(n: i32) -> Vec<i32> {
    let n = n as usize;
    let mut dp = vec![0; n + 1];
    for i in 1..=n {
        dp[i] = dp[i >> 1] + (i & 1) as i32;  // reuse the answer for i/2, plus 1 if i is odd
    }
    dp
}

fn main() {
    assert_eq!(count_bits(2), vec![0, 1, 1]);
    assert_eq!(count_bits(5), vec![0, 1, 1, 2, 1, 2]);
    assert_eq!(count_bits(0), vec![0]);  // edge: only zero itself
    assert_eq!(
        count_bits(15),
        vec![0, 1, 1, 2, 1, 2, 2, 3, 1, 2, 2, 3, 2, 3, 3, 4]
    );
    println!("counting-bits: all assertions passed");
}
Complexity: O(n) time and O(n) space — a single forward pass, each entry computed in O(1) from an earlier one.
Rust angle: Calling i.count_ones() in a loop from 0..=n would be a perfectly correct one-liner-per-element (and worth mentioning as the trivial alternative), but it's O(popcount) per call; the DP recurrence dp[i] = dp[i >> 1] + (i & 1) gets the whole table in one O(n) pass by observing that i >> 1 is i with its lowest bit dropped, so its popcount is already sitting in dp at a smaller, already-computed index. The only Rust-specific wrinkle is the type juggling: i & 1 is a usize, so it needs an explicit as i32 before it can be added to the i32 stored in dp — Rust never implicitly widens or coerces between integer types, even in an addition this trivial.

Missing Number
Given an array containing n distinct numbers taken from the range 0 to n inclusive, find the one number in that range that's missing from the array.

Example: nums = [3, 0, 1] → 2 (the full range 0..=3 has four numbers, and 2 is the one not present).
Signature
fn missing_number(nums: Vec<i32>) -> i32 { /* ... */ }
Solution — reveal after attempting (O(n) time, O(1) space — XOR every index and value against n) 
fn missing_number(nums: Vec<i32>) -> i32 {
    let n = nums.len() as i32;
    let mut result = n;  // start with n itself, since indices only range 0..n
    for (i, &num) in nums.iter().enumerate() {
        result ^= i as i32;
        result ^= num;
    }
    result
}

fn main() {
    assert_eq!(missing_number(vec![3, 0, 1]), 2);
    assert_eq!(missing_number(vec![0, 1]), 2);
    assert_eq!(missing_number(vec![9, 6, 4, 2, 3, 5, 7, 0, 1]), 8);
    assert_eq!(missing_number(vec![0]), 1);  // edge: smallest possible input
    println!("missing-number: all assertions passed");
}
Complexity: O(n) time, O(1) space — a single pass XOR-ing every index and value together.
Rust angle: The textbook alternative — sum 0..=n via the closed-form n * (n + 1) / 2 and subtract the actual sum of nums — is exactly the kind of thing that looks fine in Python (unbounded integers) but is a real liability in Rust: for a large enough n, n * (n + 1) can exceed i32::MAX and trigger attempt to multiply with overflow in a debug build before you ever get to the subtraction. XOR sidesteps that risk entirely — a ^ b can never overflow for any integer type, since every bit is independent — which makes it the structurally safer choice in Rust even before considering that it's also branch-free and doesn't need an intermediate i64 widening.

Reverse Bits
Given a 32-bit unsigned integer, reverse the order of its bits and return the resulting integer.

Example: n = 0b00000010100101000001111010011100 → 0b00111001011110000010100101000000 (the bit string is read back to front).
Signature
fn reverse_bits(n: u32) -> u32 { /* ... */ }
Solution — reveal after attempting (O(1) — 32 fixed iterations, shift a bit in from each end) 
fn reverse_bits(mut n: u32) -> u32 {
    let mut result: u32 = 0;
    for _ in 0..32 {
        result = (result << 1) | (n & 1);  // shift result left, drop in n's lowest bit
        n >>= 1;
    }
    result
}

fn main() {
    assert_eq!(
        reverse_bits(0b00000010100101000001111010011100),
        0b00111001011110000010100101000000
    );
    assert_eq!(
        reverse_bits(0b11111111111111111111111111111101),
        0b10111111111111111111111111111111
    );
    assert_eq!(reverse_bits(0), 0);  // edge: all-zero bits stay all zero
    assert_eq!(reverse_bits(1), 1u32.reverse_bits());  // idiomatic one-liner agrees with the manual loop
    println!("reverse-bits: all assertions passed");
}
Complexity: O(1) time (always exactly 32 iterations for a fixed-width integer), O(1) space.
Rust angle: The manual loop is worth knowing cold since it's the classic whiteboard ask, but n.reverse_bits() is a real standard-library method on every integer type in Rust — it compiles down to a single hardware instruction on most targets (rbit on ARM, or a handful of ops on x86), which makes "just call reverse_bits()" a legitimately correct and idiomatic production answer, not a cop-out. It's also a nice contrast with count_ones() from Number of 1 Bits: both are examples of Rust's stdlib exposing hardware bit-twiddling intrinsics directly as methods, which Python has no equivalent for without reaching into a C extension.
