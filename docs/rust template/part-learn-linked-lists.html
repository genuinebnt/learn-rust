BoxOption FoundationLearning 01
Model an Owned Singly Linked List
Prerequisites: Basic structs, enums, and heap allocation vocabulary; no earlier track card.
New idea: A recursive type needs indirection. Store the next edge as Option<Box<Node>>: None is the end and Some(Box::new(node)) owns the successor.
Hint ladder: 1) Write the node’s value first. 2) Make the next field optional. 3) Put the recursive node behind Box, then follow links with as_deref().
Complexity: Building n nodes is O(n) time and O(n) heap space; a single head link is O(1) space.
Rust angle: Box gives the recursive field a known pointer size and exclusive ownership, so no reference-counting or interior mutability is needed.
Unlocks next: Learning 02’s ownership-moving constructor and every later owned-list exercise.
Solution — reveal after attempting (owned node representation) 
#[derive(Debug, PartialEq, Eq)]
struct Node {
    value: i32,
    next: Option<Box<Node>>,
}

type Link = Option<Box<Node>>;

fn from_slice(values: &[i32]) -> Link {
    let mut head = None;
    for &value in values.iter().rev() {
        head = Some(Box::new(Node { value, next: head }));
    }
    head
}

fn to_vec(head: &Link) -> Vec<i32> {
    let mut values = Vec::new();
    let mut current = head.as_deref();
    while let Some(node) = current {
        values.push(node.value);
        current = node.next.as_deref();
    }
    values
}

fn main() {
    let empty = from_slice(&[]);
    assert_eq!(to_vec(&empty), Vec::<i32>::new());

    let list = from_slice(&[10, 20, 30]);
    assert_eq!(to_vec(&list), vec![10, 20, 30]);
    assert_eq!(list.as_ref().map(|node| node.value), Some(10));
}
movesconstruction FoundationLearning 02
Build a List by Moving Ownership
Prerequisites: Learning 01; understand that assignment normally moves a Box.
New idea: Build from right to left. Each new node takes ownership of the entire previous head as its next.
Hint ladder: 1) Start with head = None. 2) Iterate input in reverse. 3) Move head into the new node, then assign the new box back to head.
Complexity: O(n) time, O(n) node space, and O(1) auxiliary space.
Rust angle: Moving the old head is zero-copy pointer transfer. The compiler prevents two list heads from owning the same chain.
Unlocks next: Learning 03’s distinction between borrowing a chain and consuming it.
Solution — reveal after attempting (right-fold construction) 
#[derive(Debug)]
struct Node {
    value: i32,
    next: Option<Box<Node>>,
}

type Link = Option<Box<Node>>;

fn build(values: Vec<i32>) -> Link {
    values.into_iter().rev().fold(None, |head, value| {
        Some(Box::new(Node { value, next: head }))
    })
}

fn drain(mut head: Link) -> Vec<i32> {
    let mut values = Vec::new();
    while let Some(mut node) = head {
        values.push(node.value);
        head = node.next.take();
    }
    values
}

fn main() {
    assert_eq!(drain(build(vec![1, 2, 3, 4])), vec![1, 2, 3, 4]);
    assert_eq!(drain(build(vec![7])), vec![7]);
    assert_eq!(drain(build(vec![])), Vec::<i32>::new());
}

    value: i32,
    next: Option<Box<Node>>,
}

type Link = Option<Box<Node>>;

fn list(values: &[i32]) -> Link {
    let mut head = None;
    for &value in values.iter().rev() {
        head = Some(Box::new(Node { value, next: head }));
    }
    head
}

fn sum(head: &Link) -> i32 {
    let mut total = 0;
    let mut current = head.as_deref();
    while let Some(node) = current {
        total += node.value;
        current = node.next.as_deref();
    }
    total
}

fn pop_front(head: &mut Link) -> Option<i32> {
    head.take().map(|mut node| {
        *head = node.next.take();
        node.value
    })
}

fn main() {
    let mut head = list(&[4, 5, 6]);
    assert_eq!(sum(&head), 15);
    assert_eq!(pop_front(&mut head), Some(4));
    assert_eq!(sum(&head), 11);
    assert_eq!(pop_front(&mut head), Some(5));
    assert_eq!(pop_front(&mut head), Some(6));
    assert_eq!(pop_front(&mut head), None);
}
sequential accessmidpoint FoundationLearning 04
Why Ordinary Binary Search Is the Wrong Tool
Prerequisites: Learning 01–03; array binary search’s O(1) index access assumption.
New idea: Getting the kth linked node costs O(k), so repeated index-based midpoint probes erase binary search’s advantage. Fast/slow pointers find a structural midpoint in one O(n) pass when splitting is useful.
Hint ladder: 1) Implement nth by following links. 2) Count the traversed edges. 3) Advance slow once and fast twice to find the second middle without indexing.
Complexity: A single kth lookup is O(k); simulated binary search can take O(n log n). Midpoint splitting is O(n) time and O(1) space.
Rust angle: Two immutable cursors can safely borrow the same list because neither mutates it; splitting for ownership later requires moving links with take().
Unlocks next: Learning 13’s middle pattern and Learning 19/22’s midpoint-based splitting.
Solution — reveal after attempting (sequential lookup and midpoint) 
#[derive(Debug)]
struct Node {
    value: i32,
    next: Option<Box<Node>>,
}

type Link = Option<Box<Node>>;

fn list(values: &[i32]) -> Link {
    let mut head = None;
    for &value in values.iter().rev() {
        head = Some(Box::new(Node { value, next: head }));
    }
    head
}

fn nth(head: &Link, index: usize) -> (Option<i32>, usize) {
    let mut current = head.as_deref();
    let mut traversed = 0;
    for _ in 0..index {
        current = current.and_then(|node| node.next.as_deref());
        traversed += 1;
    }
    (current.map(|node| node.value), traversed)
}

fn middle(head: &Link) -> Option<i32> {
    let mut slow = head.as_deref();
    let mut fast = head.as_deref();
    while fast.and_then(|node| node.next.as_deref()).is_some() {
        slow = slow.and_then(|node| node.next.as_deref());
        fast = fast
            .and_then(|node| node.next.as_deref())
            .and_then(|node| node.next.as_deref());
    }
    slow.map(|node| node.value)
}

fn main() {
    let odd = list(&[10, 20, 30, 40, 50]);
    assert_eq!(nth(&odd, 4), (Some(50), 4));
    assert_eq!(nth(&odd, 5).0, None);
    assert_eq!(middle(&odd), Some(30));

    let even = list(&[1, 2, 3, 4]);
    assert_eq!(middle(&even), Some(3));
}

struct Node {
    value: i32,
    next: Option<Box<Node>>,
}

type Link = Option<Box<Node>>;

fn list(values: &[i32]) -> Link {
    let mut head = None;
    for &value in values.iter().rev() {
        head = Some(Box::new(Node { value, next: head }));
    }
    head
}

fn stats(head: &Link) -> (usize, i32, Vec<i32>) {
    let mut length = 0;
    let mut sum = 0;
    let mut seen = Vec::new();
    let mut current = head.as_deref();
    while let Some(node) = current {
        length += 1;
        sum += node.value;
        seen.push(node.value);
        current = node.next.as_deref();
    }
    (length, sum, seen)
}

fn main() {
    assert_eq!(stats(&list(&[])), (0, 0, vec![]));
    assert_eq!(stats(&list(&[3, -1, 8])), (3, 10, vec![3, -1, 8]));
    assert_eq!(stats(&list(&[42])), (1, 42, vec![42]));
}
insertionmutable cursor EasyLearning 06
Push Front and Append at Tail
Prerequisites: Learning 02–05.
New idea: A mutable cursor of type &mut Link points at the link to replace, including the head link itself.
Hint ladder: 1) Front insertion moves the old head into next. 2) For append, start with &mut head. 3) Advance to each node’s &mut next, then overwrite the final None.
Complexity: Push front is O(1); append is O(n) without a stored tail, both O(1) auxiliary space.
Rust angle: Cursor-to-link style avoids raw pointers and handles empty and nonempty lists with the same assignment.
Unlocks next: Learning 08 deletion and Learning 10 indexed insertion.
Solution — reveal after attempting (mutable link cursor) 
#[derive(Debug)]
struct Node {
    value: i32,
    next: Option<Box<Node>>,
}

type Link = Option<Box<Node>>;

fn push_front(head: &mut Link, value: i32) {
    let next = head.take();
    *head = Some(Box::new(Node { value, next }));
}

fn push_back(head: &mut Link, value: i32) {
    let mut cursor = head;
    while let Some(node) = cursor {
        cursor = &mut node.next;
    }
    *cursor = Some(Box::new(Node { value, next: None }));
}

fn to_vec(head: &Link) -> Vec<i32> {
    let mut out = Vec::new();
    let mut current = head.as_deref();
    while let Some(node) = current {
        out.push(node.value);
        current = node.next.as_deref();
    }
    out
}

fn main() {
    let mut head = None;
    push_back(&mut head, 2);
    push_front(&mut head, 1);
    push_back(&mut head, 3);
    assert_eq!(to_vec(&head), vec![1, 2, 3]);

    let mut singleton = None;
    push_front(&mut singleton, 9);
    assert_eq!(to_vec(&singleton), vec![9]);
}
searchearly exit EasyLearning 07
Search for a Target Value
Prerequisites: Learning 05.
New idea: Membership is a linear scan that returns immediately on the first match.
Hint ladder: 1) Borrow rather than consume the head. 2) Compare before advancing. 3) Return false only after the cursor reaches None; test empty, head-hit, tail-hit, and miss cases.
Complexity: O(n) worst-case time and O(1) space.
Rust angle: Return Option<&Node> if callers need the found node, tying its lifetime to the borrowed list; return bool for simple membership.
Unlocks next: Learning 08’s search-then-relink deletion.
Solution sketch — reveal after attempting
Use an Option<&Node> cursor. At each node, return true if the value matches; otherwise replace the cursor with next.as_deref(). If the loop ends, return false. Do not convert to a vector or use recursion for this warm-up.
deletionrelinking EasyLearning 08
Delete the First Occurrence
Prerequisites: Learning 03, 05–07.
New idea: Consume one link at a time. On a match, return the detached successor; otherwise rebuild the current node around the recursively edited suffix.
Hint ladder: 1) Match on the owned Link. 2) If the head matches, return node.next.take(). 3) Otherwise recursively delete from the detached next link and reinstall it.
Complexity: O(n) time and O(n) call-stack space in the worst case.
Rust angle: Ownership recursion makes relinking explicit and borrow-checker friendly; each box is moved exactly once and no unsafe cursor is required.
Unlocks next: Recursive structural transforms and dummy-head deletion patterns.
Solution — reveal after attempting (ownership recursion) 
#[derive(Debug)]
struct Node {
    value: i32,
    next: Option<Box<Node>>,
}

type Link = Option<Box<Node>>;

fn list(values: &[i32]) -> Link {
    let mut head = None;
    for &value in values.iter().rev() {
        head = Some(Box::new(Node { value, next: head }));
    }
    head
}

fn delete_first(head: Link, target: i32) -> Link {
    match head {
        None => None,
        Some(mut node) if node.value == target => node.next.take(),
        Some(mut node) => {
            node.next = delete_first(node.next.take(), target);
            Some(node)
        }
    }
}

fn to_vec(head: &Link) -> Vec<i32> {
    let mut out = Vec::new();
    let mut current = head.as_deref();
    while let Some(node) = current {
        out.push(node.value);
        current = node.next.as_deref();
    }
    out
}

fn main() {
    assert_eq!(to_vec(&delete_first(list(&[1, 2, 2, 3]), 2)), vec![1, 2, 3]);
    assert_eq!(to_vec(&delete_first(list(&[1, 2]), 1)), vec![2]);
    assert_eq!(to_vec(&delete_first(list(&[1, 2]), 9)), vec![1, 2]);
    assert_eq!(to_vec(&delete_first(None, 9)), vec![]);
}

struct Node {
    value: i32,
    next: Option<Box<Node>>,
}

type Link = Option<Box<Node>>;

fn list(values: &[i32]) -> Link {
    let mut head = None;
    for &value in values.iter().rev() {
        head = Some(Box::new(Node { value, next: head }));
    }
    head
}

fn collect_forward(node: Option<&Node>, out: &mut Vec<i32>) {
    if let Some(node) = node {
        out.push(node.value);
        collect_forward(node.next.as_deref(), out);
    }
}

fn collect_reverse(node: Option<&Node>, out: &mut Vec<i32>) {
    if let Some(node) = node {
        collect_reverse(node.next.as_deref(), out);
        out.push(node.value);
    }
}

fn main() {
    let head = list(&[2, 4, 6]);
    let mut forward = Vec::new();
    let mut reverse = Vec::new();
    collect_forward(head.as_deref(), &mut forward);
    collect_reverse(head.as_deref(), &mut reverse);
    assert_eq!(forward, vec![2, 4, 6]);
    assert_eq!(reverse, vec![6, 4, 2]);

    let mut empty = Vec::new();
    collect_forward(None, &mut empty);
    assert!(empty.is_empty());
}
indexed walkboundaries EasyLearning 10
Insert at a 0-Based Position
Prerequisites: Learning 05–06.
New idea: Position i identifies a link, not a node: walk a mutable &mut Link i times, then splice at that link.
Hint ladder: 1) Treat index 0 as replacing the head link. 2) On each step, advance from the current link to &mut node.next. 3) If None appears before i steps, return an error; otherwise take the suffix and install a new node before it.
Complexity: O(min(i, n)) time and O(1) space.
Rust angle: Return Result<(), InsertError> rather than silently appending on an out-of-range index; the link cursor unifies head and interior insertion.
Unlocks next: Link-level reasoning used by reversal and partitioning.
Solution sketch — reveal after attempting
Set cursor = &mut head. Repeat i times: match cursor; on Some(node), set cursor = &mut node.next; on None, return Err. Finally create Node { value, next: cursor.take() } and assign it to *cursor. Test index 0, index equal to length, and index greater than length.

reversalthree links MediumLearning 11
Iterative In-Place Reversal
Prerequisites: Learning 03, 05, 08–10.
New idea: Repeatedly detach the current head from the unprocessed suffix and push it onto the reversed prefix.
Hint ladder: 1) Name the two chains current and previous. 2) Take current.next before overwriting it. 3) Point the detached node at previous, then advance both chain heads.
Complexity: O(n) time and O(1) auxiliary space; existing nodes are reused.
Rust angle: Ownership naturally enforces the three-step detach/relink/advance order and makes accidental cycles impossible in this representation.
Unlocks next: Recursive reversal, palindrome, reorder, and k-group reversal.
Solution — reveal after attempting (owned-link reversal) 
#[derive(Debug)]
struct Node {
    value: i32,
    next: Option<Box<Node>>,
}

type Link = Option<Box<Node>>;

fn list(values: &[i32]) -> Link {
    let mut head = None;
    for &value in values.iter().rev() {
        head = Some(Box::new(Node { value, next: head }));
    }
    head
}

fn reverse(mut current: Link) -> Link {
    let mut previous = None;
    while let Some(mut node) = current {
        current = node.next.take();
        node.next = previous;
        previous = Some(node);
    }
    previous
}

fn to_vec(head: &Link) -> Vec<i32> {
    let mut out = Vec::new();
    let mut current = head.as_deref();
    while let Some(node) = current {
        out.push(node.value);
        current = node.next.as_deref();
    }
    out
}

fn main() {
    assert_eq!(to_vec(&reverse(list(&[1, 2, 3, 4]))), vec![4, 3, 2, 1]);
    assert_eq!(to_vec(&reverse(list(&[7]))), vec![7]);
    assert_eq!(to_vec(&reverse(None)), vec![]);
}

Recursive List Reversal
Prerequisites: Learning 09 and 11.
New idea: The recursive call reverses the suffix; the current frame appends its detached node to that result, or use a tail-recursive helper carrying the reversed prefix.
Hint ladder: 1) Base case: empty input returns the accumulated prefix. 2) Detach the current node’s next link. 3) Point the node to the accumulator and recurse on the detached suffix; verify that each call strictly shortens the input.
Complexity: O(n) time and O(n) call-stack space.
Rust angle: Rust does not guarantee tail-call optimization, so the iterative Learning 11 version is safer for unbounded lists even when the recursive helper is conceptually clean.
Unlocks next: Recursive divide-and-conquer over owned chains.
Solution sketch — reveal after attempting
Write reverse_into(current, previous). If current is None, return previous. Otherwise take the boxed node, detach node.next as the next current, point node.next at previous, and recurse with Some(node) as the accumulator. Assert empty, singleton, and multi-node cases.
fast / slowmiddle MediumLearning 13
Find the Middle with Fast and Slow Cursors
Prerequisites: Learning 04–05.
New idea: When fast advances two edges for each slow edge, slow reaches the midpoint when fast reaches the end.
Hint ladder: 1) Borrow two cursors from the same head. 2) Continue only while fast has a successor. 3) Advance slow once and fast twice; state explicitly whether even-length input returns the first or second middle, then test it.
Complexity: O(n) time and O(1) space.
Rust angle: Immutable aliases are legal; trying to mutate through slow while fast still borrows the chain is not. Separate discovery from ownership-changing split operations.
Unlocks next: Cycle detection, remove-from-end gaps, palindrome halves, reorder, and merge sort.
Solution sketch — reveal after attempting
Use Option<&Node> for both cursors. While fast.and_then(|n| n.next.as_deref()) exists, move slow one link and fast two links. Returning slow then chooses the second middle for even lengths. Test lengths 0 through 5 so the convention is unmistakable.
cycle detectionidentity MediumLearning 14
Detect a Cycle and Locate Its Entry
Prerequisites: Learning 13 and the difference between value equality and node identity.
New idea: Floyd’s tortoise/hare meeting proves a cycle; resetting one cursor to the head and advancing both one step locates the entry.
Hint ladder: 1) The owned Box list cannot form a safe cycle, so model this exercise with Rc<RefCell<Node>>. 2) Compare identity with Rc::ptr_eq, never node values. 3) After a meeting, reset one cursor to head and move both one edge until identities match.
Complexity: O(n) time and O(1) algorithmic cursor space; nodes use reference counts.
Rust angle: Cycles require shared ownership and can leak with strong Rc edges. Production parent/back links often use Weak; this algorithm deliberately models graph-like identity.
Unlocks next: Identity-sensitive intersection and random-pointer copying.
Solution sketch — reveal after attempting
Define type Link = Option<Rc<RefCell<Node>>> and a helper that clones a node’s next Rc after a short borrow. Move slow once and fast twice until Rc::ptr_eq reports a meeting or fast reaches None. For the entry phase, advance a head cursor and the meeting cursor one step together. Include acyclic, self-cycle, and interior-entry tests.
sorted mergedummy head MediumLearning 15
Merge Two Sorted Lists
Prerequisites: Learning 08 and 11; sorted-order invariant.
New idea: Repeatedly detach the smaller head node and append it to a result tail; a dummy node removes the special case for the first append.
Hint ladder: 1) Compare through as_ref() before moving. 2) Take one list head and detach its next link. 3) Append that existing box to tail.next, advance tail, then attach the nonempty remainder.
Complexity: O(n + m) time and O(1) auxiliary space.
Rust angle: The merge reuses boxes rather than cloning values. At every moment, each remaining chain and result chain has exactly one owner.
Unlocks next: Stable partitioning, merge sort, merge-k, and zipper-style list assembly.
Solution — reveal after attempting (node-reusing merge) 
#[derive(Debug)]
struct Node {
    value: i32,
    next: Option<Box<Node>>,
}

type Link = Option<Box<Node>>;

fn list(values: &[i32]) -> Link {
    let mut head = None;
    for &value in values.iter().rev() {
        head = Some(Box::new(Node { value, next: head }));
    }
    head
}

fn merge(mut a: Link, mut b: Link) -> Link {
    let mut dummy = Box::new(Node { value: 0, next: None });
    let mut tail = &mut dummy;

    while a.is_some() && b.is_some() {
        let take_a = a.as_ref().unwrap().value <= b.as_ref().unwrap().value;
        let mut node = if take_a {
            let mut node = a.take().unwrap();
            a = node.next.take();
            node
        } else {
            let mut node = b.take().unwrap();
            b = node.next.take();
            node
        };
        node.next = None;
        tail.next = Some(node);
        tail = tail.next.as_mut().unwrap();
    }
    tail.next = if a.is_some() { a } else { b };
    dummy.next
}

fn to_vec(head: &Link) -> Vec<i32> {
    let mut out = Vec::new();
    let mut current = head.as_deref();
    while let Some(node) = current {
        out.push(node.value);
        current = node.next.as_deref();
    }
    out
}

fn main() {
    let merged = merge(list(&[1, 3, 5]), list(&[1, 2, 6]));
    assert_eq!(to_vec(&merged), vec![1, 1, 2, 3, 5, 6]);
    assert_eq!(to_vec(&merge(None, list(&[4, 8]))), vec![4, 8]);
    assert_eq!(to_vec(&merge(None, None)), vec![]);
}

Prerequisites: Learning 05, 13–14.

Hint ladder: 1) Use a shared-tail representation such as Rc<Node>; plain owned Box chains cannot share a tail. 2) Compute both lengths. 3) Advance the longer head by the difference, then step both and compare with Rc::ptr_eq.
Complexity: O(n + m) time and O(1) cursor space.
Rust angle: Choose representation from topology: exclusive Box for trees/chains, Rc for immutable shared tails, and Rc<RefCell<_>> only if mutation is required.

struct Node {
    value: i32,
    next: Option<Box<Node>>,
}

type Link = Option<Box<Node>>;

fn list(values: &[i32]) -> Link {
    let mut head = None;
    for &value in values.iter().rev() {
        head = Some(Box::new(Node { value, next: head }));
    }
    head
}

fn length(head: &Link) -> usize {
    let mut n = 0;
    let mut current = head.as_deref();
    while let Some(node) = current {
        n += 1;
        current = node.next.as_deref();
    }
    n
}

fn is_palindrome(head: Link) -> bool {
    let n = length(&head);
    let mut current = head;
    let mut left = None;

    for _ in 0..n / 2 {
        let mut node = current.take().unwrap();
        current = node.next.take();
        node.next = left;
        left = Some(node);
    }

    if n % 2 == 1 {
        current = current.unwrap().next;
    }

    let mut a = left.as_deref();
    let mut b = current.as_deref();
    while let (Some(left_node), Some(right_node)) = (a, b) {
        if left_node.value != right_node.value {
            return false;
        }
        a = left_node.next.as_deref();
        b = right_node.next.as_deref();
    }
    a.is_none() && b.is_none()
}

fn main() {
    assert!(is_palindrome(list(&[])));
    assert!(is_palindrome(list(&[7])));
    assert!(is_palindrome(list(&[1, 2, 2, 1])));
    assert!(is_palindrome(list(&[1, 2, 3, 2, 1])));
    assert!(!is_palindrome(list(&[1, 2, 3])));
}

#[derive(Debug)]
struct Node {
    value: i32,
    next: Option<Box<Node>>,
}

type Link = Option<Box<Node>>;

fn list(values: &[i32]) -> Link {
    let mut head = None;
    for &value in values.iter().rev() {
        head = Some(Box::new(Node { value, next: head }));
    }
    head
}

fn add(mut a: Link, mut b: Link) -> Link {
    let mut carry = 0;
    let mut dummy = Box::new(Node { value: 0, next: None });
    let mut tail = &mut dummy;

    while a.is_some() || b.is_some() || carry != 0 {
        let av = a.as_ref().map_or(0, |node| node.value);
        let bv = b.as_ref().map_or(0, |node| node.value);
        let sum = av + bv + carry;
        carry = sum / 10;

        tail.next = Some(Box::new(Node { value: sum % 10, next: None }));
        tail = tail.next.as_mut().unwrap();

        if let Some(mut node) = a {
            a = node.next.take();
        }
        if let Some(mut node) = b {
            b = node.next.take();
        }
    }
    dummy.next
}

fn to_vec(head: &Link) -> Vec<i32> {
    let mut out = Vec::new();
    let mut current = head.as_deref();
    while let Some(node) = current {
        out.push(node.value);
        current = node.next.as_deref();
    }
    out
}

fn main() {
    assert_eq!(to_vec(&add(list(&[2, 4, 3]), list(&[5, 6, 4]))), vec![7, 0, 8]);
    assert_eq!(to_vec(&add(list(&[9, 9]), list(&[1]))), vec![0, 0, 1]);
    assert_eq!(to_vec(&add(None, list(&[3, 2]))), vec![3, 2]);
    assert_eq!(to_vec(&add(None, None)), vec![]);
}

Solution sketch — reveal after attempting (four separate variants)
Variant A — Merge k sorted lists: For divide-and-conquer, repeatedly merge adjacent pairs with Learning 15 until one list remains; this gives O(N log k) comparisons and reuses boxes.
