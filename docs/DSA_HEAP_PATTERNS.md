# Heap / Priority Queue patterns: the exhaustive target list

Every heap and priority-queue pattern that can come up on LeetCode, as the target for the Heap / Priority Queue pattern lessons, in the format of [DSA_GRAPH_PATTERNS.md](DSA_GRAPH_PATTERNS.md). The rule is in [DSA.md](DSA.md), decision 32: a topic's patterns section is exhaustive, patterns without a NeetCode problem get **example problems** from LeetCode, and variants of one pattern (the size-k heap / sort and slice) are **tabs** of one lesson.

Status: documented only. Today `content/dsa/lessons/heap-priority-queue.toml` has 7 techniques (size-k, pool, quickselect, cooldown, schedule-sim, two-heaps, greedy-heap). Building the rest needs a mockup of the tabs first, then lessons and picked example problems. Several groups below (heaps in graph algorithms, heaps on grids, k-way merge, scheduling with intervals, the order-statistic alternatives) overlap lessons that already live in other topics (Advanced Graphs, Linked List, Intervals, Sliding Window, Arrays & Hashing); whether those lessons are linked or duplicated is an open question (see Gaps).

Items written *a / b* in a group are variants for tabs where one lesson covers both (for example "K largest or smallest items: size-k heap / sort and slice"). Each item is one lesson; the numbering (1.1, 1.2, ...) is used again in the example list below.

1. **Top-k selection.** K largest or smallest items: size-k heap / sort and slice / heapq.nlargest; The k-th largest of a stream: min-heap of size k; Top k by frequency: count then heap / bucket sort; K closest to a point or value: max-heap of size k on the distance; Top k per group: one small heap per key; Tiny k: a few variables or heappushpop instead of a full heap; Quickselect: three-way partition / random pivot / Hoare partition.
2. **Two heaps and the median.** Running median: max-heap for the lower half, min-heap for the upper half; Sliding-window median: two heaps with delayed removal / sorted list; Pending pool and ready pool: sort by the unlock key, move items into the heap as they unlock; Opposing books: a buy heap against a sell heap; Rank tracker: the k-th element is the boundary between two heaps; Candidates from both ends: two heaps, each holding one side's cheapest k.
3. **K-way merge.** Merge k sorted lists: heap of heads / divide and conquer on pairs; Merge k sorted arrays or streams lazily: generator, heapq.merge; K smallest pairs from two sorted arrays: expand a frontier from (0, 0); K-th smallest in a sorted matrix: heap of row heads / binary search on the value; Smallest range covering one element of each list: heap with a running maximum; Latest items from many sorted feeds: merge per-user lists by time; Numbers generated by merging multiples: ugly numbers, super ugly numbers; Merge sorted interval lists: free time across employees; Sort a k-sorted array: a heap window of k + 1; External merge: sorted runs too large for memory.
4. **Scheduling with heaps.** Shortest available job first on one worker: ready heap plus a clock; Several workers or servers: a free heap and a busy heap; Rooms and resources: min-heap of end times; Cooldown: max-heap of counts plus a waiting queue; Rearranging with a gap: no two equal neighbours / at least k apart; Deadlines: take everything, drop the longest job when over the limit; Attend the most events: earliest deadline first; Sweep line with an active set in a heap: skyline, interval queries; Capacity along a route: heap of drop-off points; Smallest free slot: heap of released ids.
5. **Greedy with a heap.** Take the extreme, transform it, put it back: smash, merge, take gifts; Shrink the biggest each step: halve, remove stones, increment the smallest; Regret greedy: act now, undo the worst choice later (bricks, refuelling, courses); Best marginal gain: the next step with the biggest improvement; Sort by one key, keep the best k of the other in a heap: hire, team, elegance; Pairing by differences: the k items with the largest gain; Build a string by counts under a limit: take the biggest letter that is allowed; Greedy by rank: biggest value to the biggest weight; sorting is often enough.
6. **Heaps in graph algorithms.** Dijkstra: shortest weighted path with a min-heap; Dijkstra with a constraint in the state: stops, time, deadlines; Minimax and maximin paths: minimum effort, rising water, safest path; Prim's minimum spanning tree: heap of crossing edges; Best-first search and A*: priority is cost plus a heuristic; Topological order with a priority queue: lexicographically smallest order; Lexicographically smallest Eulerian itinerary: Hierholzer with a heap; 0-1 BFS / Dijkstra: weights of 0 and 1 on a grid; Offline queries: sort the thresholds, grow the reachable region with a heap; Boundary-in flooding: pop the lowest wall (trapping rain water II); Time-gated edges and cells: wait at a node until it opens; Dijkstra on an implicit state graph / combined with binary search; K shortest paths: let each node pop up to k times.
7. **Lazy deletion and indexed heaps.** Lazy deletion: skip stale entries when they surface (map value / version stamp / removed set); Delayed removal counters: keep two heaps balanced after a removal; Sliding-window maximum with a heap: store the index, pop while it is outside the window; DP transitions that need a window maximum: heap with an index check; Re-push instead of decrease-key (Dijkstra, best-first); Indexed heap with decrease-key: a position map beside the array; Remove an arbitrary item: swap with the last, sift both ways; Pop and skip invalid entries: marked elements, merged neighbours.
8. **Comparators and tie-breaking.** Max-heap by negating numbers; Tuple priorities: (priority, tie-breaker, item) so items are never compared; Orders that cannot be negated: strings, descending words, numbers stored as strings; A wrapper class or comparator: __lt__ in Python, Ord with Reverse in Rust; Ratios and fractions as priorities: compare by cross-multiplication, not floats; Ties by arrival: a counter makes equal priorities first-in first-out; Lexicographic goals: the smallest letter first, ties by index.
9. **Heapify and heap sort.** Build a heap in O(n): sift down from the middle versus n pushes; Heap sort in place: build, then swap the root to the end and sift; Write the heap yourself: array layout, parent at (i - 1) // 2, sift-up and sift-down; The library API: heappushpop, heapreplace, nsmallest, nlargest, merge; Partial sort: heapify then k pops, O(n + k log n); Other heaps: d-ary, pairing, Fibonacci, binomial; Double-ended priority queue: min-max heap, or two heaps with lazy deletion.
10. **Design problems with heaps.** Kth Largest in a stream: a class around a size-k heap; Median finder: add a number, read the median; Release the smallest free id: seat reservation, chairs; News feed: per-user lists merged on read; Ratings, containers and task systems: the top entry by key, with updates; Stock price with latest, maximum and minimum; Autocomplete and suggestions: the top k hot completions; Windows and counters over a stream: a queue or a hash map, no heap needed; Online queries over a stream: monotonic stack, prefix products, counting hash; Designs on a list or deque, no heap (the contrast case).
11. **Heap plus hash map.** Count first, then heap by count; The map holds the truth; heap entries are checked against it when they surface; Group by key, one heap (or the best two) per key; Greedy over counts: pop the biggest, re-push what remains; Counts that change over time: id to count updates, then read the maximum.
12. **Heaps on grids.** Dijkstra on a grid: the cost of a cell depends on the path to it; Rising boundary: water level or flood from the outside in; Nearest ranked items: BFS from the start, then the top k by rank; Safest path: multi-source BFS distances, then a max-heap path; Cost of changing direction: 0-1 BFS or Dijkstra; Queries sorted by threshold, expanding the region with a heap; K-th smallest in a sorted matrix; Cells ordered by a key, popped in order (diagonals, ranks); Pair points by distance: all pairs in a heap, take the nearest valid one; Time-gated cells: arrive no earlier than the cell opens.
13. **Huffman coding and merge costs.** Merge the two cheapest until one is left (connect sticks, ropes); Huffman coding tree: build the code from the frequencies; Huffman in O(n) after sorting: two queues instead of a heap; Merges with a non-additive cost: greedy fails, use interval DP; Take two, put one back, or process the smallest two as a pair: smash, number game.
14. **Order-statistic alternatives.** Sort once and slice, when all the data is in memory; Bucket or counting sort when keys are small integers; Ordered set (balanced tree, sorted list): neighbours and rank with removal; Binary search on the value: how many items are at most x?; Fenwick or segment tree for ranks and prefix counts; Monotonic deque for sliding extremes; Median of medians: worst-case linear selection; Treap, order-statistic tree, skip list; Binary search on sorted events instead of a heap sweep; Union-find instead of a heap for bottleneck paths; Counting array for a streaming median over bounded values.
15. **Core implementation patterns.** the heapq functions (heappush, heappop, heappushpop, heapreplace, heapify, nlargest, nsmallest, merge); a min-heap only, so negate for a maximum; tuples (priority, tie-breaker, item); the size-k invariant: the root is the item to throw out; the heap is not sorted, only its root is ordered; heapify is O(n), n pushes is O(n log n); stale-entry check on pop; pop only when the heap is non-empty; Rust: BinaryHeap is a max-heap, wrap in Reverse for a min-heap; the number of pops needed versus sorting everything.
