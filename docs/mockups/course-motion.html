Grow the file and reuse slots

test this stageanneal course test 1a-04
YOU'LL LEARNgrowing a file by whole pagesa free list of slotsreusing deleted space
READ FIRSTDurability: when a write is really on disk · and 2 more~27 min

A page-sized file grows one page at a time1. When a page is deleted its slot goes on a free list2 so the next allocation reuses it instead of growing the file again.

1A page is PAGE_SIZE bytes (4096 here), so the file length is always a multiple of it.
2BusTub calls this free_slots_. Why a stack and not a queue? See the check-yourself question below.

The free list is a plain Vec used as a stack3: push a page id when it is deleted, pop one when you need a page.

3Push on delete, pop on allocate: 
pub fn free(&mut self, id: PageId) {
    self.free.push(id);
}
pub fn alloc(&mut self) -> Option<PageId> {
    self.free.pop() // LIFO: last freed, first reused
}

TIP

Write the failing test first: reuses_a_freed_slot tells you exactly what the free list must do.

i
NOTE

A page id is the file offset divided by the page size, so the file length alone says how many pages exist.

!
WATCH OUT

Zero a reused page before handing it back, or the next reader sees the previous owner's bytes.

×
DON'T

Never call set_len while the free list still has a slot: the file grows forever.

B
IN BUSTUB

BusTub's DiskManager::AllocatePage does the same with a std::vector<page_id_t> free list.

⇄
PORT RULE

Every std::vector::pop_back becomes Vec::pop, which returns an Option.

A queue would reuse the page freed longest ago; a stack reuses the one freed most recently. The stack keeps the working set small and warm: that page is likely still in the buffer pool.

let mut free: Vec<PageId> = Vec::new();
free.push(3);
free.push(7);
assert_eq!(free.pop(), Some(7)); // most recent first

pub fn allocate_page(&mut self) -> PageId {
    if let Some(id) = self.free.pop() {
        self.zero(id);
        return id;
    }
    let id = self.pages; // grow by one page
    self.pages += 1;
    id
}
