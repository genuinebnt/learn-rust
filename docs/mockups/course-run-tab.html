What changes

  1. Failures first and open. A failing test shows its message without a click; tests that share the same message are marked, as the CLI report already does.
  2. Passes folded. One row summarises them; click to see every name. When nothing fails the list opens by itself.
  3. Segmented bar with one segment per test in test order, so a run reads at a glance.
  4. Run-again command with a copy button; --only is the filter the CLI already has.
  5. Compiler errors in their own block, as the stage page's compiler panel shows them.

Not in this mockup, and why: per-test durations and grouping by stage. A reported run is for one stage and carries only the total time; cargo test gives per-test times only on nightly. Both would need the runner and the report format to change, so I left them out. The hint line under the first failure is optional: it would come from an optional why on the stage’s test list, which does not exist today.
