Shifts and masks on u32.

How to keep the top bits or the low bits of a number, and the edge case that is a panic in Rust and undefined behaviour in C.

A shift moves every bit

x >> n moves every bit of x right by n places. The low n bits fall off the end, and zeros come in from the left (for unsigned types like u32).

0b1011_0110 >> 4
= 0b0000_1011     // the low four bits 0110 are gone

x << n is the mirror image: bits move left, the high ones fall off, zeros come in from the right. Shifting left by 1 doubles a number, as long as nothing falls off.

Keeping the top bits

To keep only the top k bits of a u32, shift right by 32 - k: everything below them falls off.

x            = 1010 0000 0000 0000 0000 0000 0000 0001
x >> (32 - 3) = 0000 0000 0000 0000 0000 0000 0000 0101   = 5

The extendible hash table's header page does exactly this to pick a directory: the top max_depth bits of the hash.

QUICK CHECK

With k = 2, what is 0xC000_0000 >> (32 - 2)?

0xC000_0000 starts with the bits 11, which is 3.

Keeping the low bits: a mask

To keep only the low k bits, and with a mask of k ones: (1 << k) - 1.

k = 3:  (1 << 3) - 1 = 0b1000 - 1 = 0b0111

  0b1101_0110
& 0b0000_0111
= 0b0000_0110   = 6

The directory page uses this one: a hash's low global_depth bits pick its bucket slot (stage 2b-06).

The edge: shifting by the full width

What is x >> 32 on a u32? You might expect 0. Instead:

Rust, debugpanic: attempt to shift right with overflowRust, releasethe amount is masked to 5 bits: x >> 0, which is xC and C++undefined behaviour

So hash >> (32 - max_depth) breaks when max_depth is 0. Give 0 its own case, or use a method that says what happens at the edge.

QUICK CHECK

In a release build, with let n = 32;, what is 1u32 << n?

Release builds turn off overflow checks, and the shift amount is masked to the low 5 bits: 32 becomes 0, so the result is 1 << 0 = 1. The same code panics in a debug build.

Methods that name the edge

hash.checked_shr(32)          // None: the amount is too big
hash.checked_shr(32).unwrap_or(0)   // 0, the answer you wanted
hash.wrapping_shr(32)         // hash: masks the amount, like release

A match with a 0 => 0 arm is just as good. What matters is that you looked at 0 and at the type's width.

Recap

  • x >> (32 - k) keeps the top k bits.
  • x & ((1 << k) - 1) keeps the low k bits.
  • Every data-dependent shift needs a look at 0 and at the width: Rust panics in debug, C and C++ are undefined.
