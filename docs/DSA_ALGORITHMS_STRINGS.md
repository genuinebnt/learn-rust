# String algorithms: the exhaustive target list

The target list (2026-10-10) of every string algorithm and technique that can come up on LeetCode or in an interview, as the target for
the Strings pattern lessons (and the string-heavy parts of Tries, Sliding Window, Stack and Dynamic Programming). The rule is in
[DSA.md](DSA.md), decision 32: a topic's patterns section is exhaustive, patterns without a NeetCode problem get **example problems**
from LeetCode, and variants of one pattern (recursive / iterative) are **tabs** of one lesson. The format follows
[DSA_GRAPH_PATTERNS.md](DSA_GRAPH_PATTERNS.md); [DSA_ALGORITHMS_NUMBER_THEORY.md](DSA_ALGORITHMS_NUMBER_THEORY.md) is the sibling
catalogue for numbers.

Status: documented only. Today the string techniques sit inside the Arrays & Hashing, Two Pointers, Sliding Window, Stack, Tries and
1-D / 2-D Dynamic Programming lessons (hashing of anagram keys, window counting, bracket stacks, trie insert / search, LCS and edit
distance); most of the list below (KMP, Z, Aho-Corasick, Manacher, suffix structures, rolling hashes, Lyndon words, compression) has no
lesson yet. Building the rest needs a mockup of the tabs first, then lessons and picked example problems. Plain bit tricks live in the
Bit Manipulation topic, big-number string arithmetic (add / multiply strings) in the number-theory catalogue, and graph search over word
spaces (word ladder, alien dictionary) in [DSA_GRAPH_PATTERNS.md](DSA_GRAPH_PATTERNS.md); they are cross-referenced here, not repeated.

Items written *a / b* in a group are variants for tabs where one lesson covers both (for example "Boyer-Moore: bad character / good
suffix"). A *Z / prefix function* style item names two algorithms that solve the same problem and are taught side by side.
