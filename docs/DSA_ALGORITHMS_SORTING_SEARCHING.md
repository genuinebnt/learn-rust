# Sorting, searching, selection and randomized algorithms: the exhaustive target list

The owner's rule from [DSA.md](DSA.md), decision 32, applied to **algorithms** rather than to one topic's patterns: a topic's lessons are
exhaustive, algorithms and techniques without a NeetCode problem get **example problems** from LeetCode, and variants of one algorithm
(top-down / bottom-up merge sort) are **tabs** of one lesson. This file is the catalogue for sorting, searching, selection, divide and
conquer, randomized and approximate algorithms, amortised and online analysis. The graph counterpart is
[DSA_GRAPH_PATTERNS.md](DSA_GRAPH_PATTERNS.md).

Status: documented only. Today there is no Sorting track. Related lessons that exist are `binary-search.toml` (8 techniques: classic,
insert-pos, by-count, on-answer, rotated, weighted, partition, peak), `heap-priority-queue.toml` (7, including quickselect and
two-heaps), the `sorting` and `top-k` techniques in `arrays-hashing.toml`, `merge-sorted` in `two-pointers.toml` and `kway-merge` in
`linked-list.toml`. Building the rest needs a mockup of the tabs first (rule 13), then lessons and picked example problems.

Items written *a / b* in a group are variants for tabs where one lesson covers both (for example "merge sort: top-down / bottom-up").
An item with a parenthesis names the knobs the lesson would cover. "(cross-reference)" means the algorithm already has a lesson in
another topic and the entry here only links to it.

1. **Elementary and quadratic comparison sorts.** Bubble sort (early exit when no swap, bidirectional pass) / cocktail shaker sort; selection sort (fewest writes, double selection); insertion sort (linear and binary-insertion variants, the base case of every hybrid, best case O(n) on nearly sorted input); gnome sort; shell sort (gap sequences: Shell, Knuth, Sedgewick, Ciura); comb sort; odd-even (brick) sort; stooge sort / slowsort / bogosort (names only, what they teach about recurrences); counting swaps as the cost model.
2. **Merge sort family.** Merge sort: top-down (recursive) / bottom-up (iterative, width doubling); the two-way merge routine (sentinel / index form, stable by taking the left on ties); auxiliary buffer reuse and ping-pong copy; switch to insertion sort below a cutoff; natural merge sort (merge existing runs); in-place merge / block merge (rotation based); linked-list merge sort (split by fast and slow pointers, no extra space); parallel merge sort; merge sort tree (cross-reference to range queries); recurrence T(n) = 2T(n/2) + n.
3. **Quicksort family and partitioning.** Partition schemes: Lomuto / Hoare; three-way partition (Dijkstra, equal keys in the middle); random pivot / median-of-three / ninther; dual-pivot quicksort; recursing on the smaller side and eliminating tail calls (O(log n) stack); introsort (depth limit then heap sort); pdqsort (pattern-defeating, fall-back detection); quicksort on linked lists; adversarial and already-sorted inputs; expected comparisons 2n ln n; the partition step as a reusable primitive (quickselect, Dutch national flag, parity split).
4. **Heap, tree and tournament sorts.** Heap sort (build-heap in O(n), sift-down / sift-up, in-place max-heap); smoothsort / weak-heap sort (names, adaptive heaps); tree sort (BST in-order, balanced tree for the worst case); tournament sort / loser tree (selection from k streams, replacement selection for run generation); patience sort (piles, link to the LIS length); library sort (gapped insertion); Cartesian tree sort (names, linear time on nearly sorted input).
5. **Hybrid, adaptive and in-place permutation sorts.** Tim sort (natural runs, minrun, galloping mode, stack invariants, why Python and Java use it); introsort / pdqsort as library defaults; block sort / WikiSort (stable in-place); adaptive sorting measured in runs and inversions; cycle sort (minimum writes, one cycle per misplaced element); cyclic sort / index placement (each value goes to its own index, find the missing and duplicate ones); sorting networks (bitonic, odd-even merge; fixed comparator schedules, 0-1 principle); pancake sort and sorting by prefix reversal (names); permutation cycles and in-place permutation application.
6. **Non-comparison sorts.** Counting sort (prefix-sum form is stable, plain form for small ints and characters); radix sort: LSD / MSD (digit base choice, stable inner sort, negative numbers, fixed-width strings, variable-length strings); bucket sort (uniform input, per-bucket insertion sort, value-range and frequency buckets); pigeonhole sort; flash sort; American flag sort (in-place MSD radix); spreadsort / burst sort (names); three-way radix quicksort for strings; sorting integers in O(n) with radix base n; sorting by key range when max - min is small; the O(n log n) comparison lower bound and why these sorts escape it.
7. **Sorting properties and theory.** Stable vs unstable (what stability buys: multi-key sorting by sorting on the least significant key first; making an unstable sort stable by appending the original index); in-place vs auxiliary space; adaptive and online sorts; comparison-sort lower bound via the decision tree (log2 n! comparisons); best / average / worst table for every sort above; sorting cost vs hashing cost (when to sort to group, when to hash); decorate-sort-undecorate (key functions, Schwartzian transform); partial sort / nth_element / is_sorted_until; checking sortedness and minimum swaps to sort; sorting linked lists vs arrays (random access, cache behaviour); sort algorithms in standard libraries (Python Timsort, Rust `sort` vs `sort_unstable`, C++ introsort).
8. **Sorting applications.** Custom comparators and key functions (multi-key, descending on one key, tuple keys); sort by frequency / by custom order string; largest number (comparator a+b vs b+a); wiggle sort I / II (sort then interleave, or median plus three-way partition); Dutch national flag / sort colours (three-way partition in one pass); parity partition; sort by bit count / by transformed key; sorting with constraints (swap only within connected components: sort each component; sort by indices allowed to swap); sort then scan (duplicates, closest pair, intervals, meeting rooms, greedy after sort); sort then two pointers; sort then binary search; relative sort (counting plus custom order); sorting strings and lexicographic order; minimum swaps / chunks to make sorted; sort a nearly sorted (k-sorted) array with a heap.
9. **Merging sorted sequences and k-way merge.** Merge two sorted arrays / lists (from the back for in-place); merge k sorted lists: heap / divide-and-conquer pairwise merge / tournament tree; k-way merge of arrays (smallest range covering k lists, k smallest pairs, kth smallest in a sorted matrix as a merge of rows); merge intervals and interval list intersections (cross-reference to Intervals); union / intersection / difference of sorted sets; merging with deduplication and with stability; streaming merge with lazy iterators; merge cost analysis (Huffman-order merging, optimal merge pattern).
10. **External, parallel and cache-aware sorting.** External merge sort (run generation with a memory budget, replacement selection, k-way merge passes, number of passes = ceil(log_k (N / M))): the BusTub course covers this in module 18 (sorting, limits and windows) and the concept article `external-merge-sort`, so the lesson here is a cross-reference plus the interview framing "sort 100 GB with 1 GB of RAM"; distribution / sample sort; top-N heap sort (ORDER BY ... LIMIT, bounded heap instead of a full sort); parallel merge sort and parallel partition (names); cache-oblivious sorting / funnelsort (names); sorting on disk vs SSD (I/O cost model, sequential vs random); bucketing by range or hash then sorting each bucket (the external bucket sort).
11. **Counting inversions and pairs by order.** Inversions by merge sort (count while merging); inversions by Fenwick tree / BIT (coordinate compression, process left to right); inversions by segment tree / order-statistic tree; reverse pairs and important inversions (count then merge, two-pointer in the merge step); count of smaller numbers after self; count of range sums (prefix sums plus merge sort or BIT); count of pairs with a condition by sort plus two pointers / binary search; minimum adjacent swaps to sort (equals inversions); Kendall tau distance (names); permutation inversion count DP (count permutations with k inversions, cross-reference to DP).
12. **Order statistics and selection.** Quickselect (partition around a random pivot, expected O(n), iterative form); median of medians (deterministic O(n), groups of 5, why 5); introselect (quickselect with a fall-back); kth element in two sorted arrays (binary search on the partition, median of two sorted arrays); k-th smallest in a sorted matrix (heap, binary search on value with a staircase count); k-th smallest pair distance / k-th smallest product (binary search on value plus two pointers); selection by counting (small value range); kth smallest in a BST (in-order, order-statistic augmentation); kth element in a merged k lists; median of an array (selection vs sort); selecting the k-th lexicographic element (cross-reference to tries and combinatorics); Floyd-Rivest (name only).
13. **Top-k and median maintenance.** Top-k with a size-k heap (min-heap for the largest, bounded memory) / with quickselect (O(n) average, mutates the array) / with bucket sort by frequency (O(n), count-indexed buckets); top-k by full sort (when n is small); k closest points; kth largest in a stream; two heaps for a running median / sliding-window median (two heaps with lazy deletion, or an ordered multiset / treap); median with a value-range counting array or a BIT; top-k frequent words with tie-break; merging top-k from shards; approximate heavy hitters (Misra-Gries, Boyer-Moore majority vote, count-min sketch: names, cross-reference to Arrays & Hashing); percentile tracking (t-digest, names).
14. **Linear search and binary search foundations.** Linear search (sentinel search, early exit); self-organising lists (move-to-front, transpose); binary search templates: closed interval `[lo, hi]` / half-open `[lo, hi)` as tabs of one lesson; exact match; lower bound / upper bound; first and last occurrence; insertion position; count of occurrences as upper minus lower; floor / ceil / nearest value; largest value not exceeding x; binary search on indices vs on values; the invariant-first way of writing the loop; searching a sorted array of objects by a key; library functions (`bisect`, `partition_point`).
15. **Binary search on structured inputs.** Rotated sorted array: distinct / with duplicates (the degenerate shrink-by-one case); find the minimum in a rotated array; find the rotation point; peak element / mountain array (compare mid with mid + 1); search in a mountain array (peak then two binary searches); 2-D matrix: flatten to one index / row-and-column staircase walk from a corner; search in an array of unknown size (exponential bounds first); binary search in a sorted array of lists / prefix sums (pick by weight); first bad version / guess-the-number (interactive predicate); single element in a sorted pair array (binary search on parity of index); missing element in a sorted array (compare value with index); binary searchable elements in an unsorted array; binary search over a BST / over sorted keys of a map (time-based key-value store); binary search over a sorted list of intervals; binary lifting as bitwise binary search (cross-reference to trees).
16. **Other search algorithms.** Exponential (galloping) search (unbounded and merge-galloping in Tim sort); interpolation search (uniform keys, O(log log n) expected, bad on skew); jump search (block size sqrt n); fibonacci search (division by addition only); ternary search on a unimodal array / function; golden-section search (reuses one probe); ordered-set and balanced-BST search (cross-reference to Trees); hash lookup vs sorted lookup (when to pre-sort); search in a skip list; search by sentinel; search with a comparison oracle / interactive problems (limited queries, `guess`, `compare`); search in a bitonic array; search in a sorted array with an unknown order.
17. **Binary search on the answer: monotone predicates.** The recipe: define `feasible(x)`, check monotonicity, bound the range, write the greedy checker, search for the first true; parametric search; minimise the maximum / maximise the minimum (split array largest sum, aggressive cows, magnetic force, divide chocolate); capacity problems (ship within d days, painter's partition, bouquets in k days); rate problems (eating bananas, minimum speed to arrive on time, repair cars, complete trips); counting-based k-th value (k-th smallest pair distance, k-th smallest in a multiplication table, k-th smallest product); search on the answer combined with a graph check (minimum effort path, bottleneck path, safest path: cross-reference to Graphs); search on the answer with a sliding window / two-pointer checker; search on the answer with a DP checker (house robber IV, minimise the maximum difference of pairs); searching for the largest k for which a prefix works (binary search on the length: longest repeated subarray, longest duplicate substring with rolling hash); binary search on a sorted-by-construction function (nth digit, arranging coins, perfect square, missing element); allocation / distribution (candies to k children, cutting ribbons, minimised maximum of products to stores); bounds and the empty-range pitfall.
18. **Search on real numbers and unimodal functions.** Binary search on real numbers (fixed iteration count vs epsilon, precision and monotone floating-point pitfalls: gas station, maximum average subarray, separate squares); bisection for roots; Newton's method (integer square root, convergence, fallback to binary search); ternary search for the maximum of a unimodal function (integers and reals); golden-section search; fractional programming / Dinkelbach (binary search on the ratio); binary search on a convex or monotone cost for aggregation (sum of absolute deviations); gradient descent and convex minimisation (names, when they appear); binary search with a floating check using relative error; exponentiation by squaring as the binary-split cousin (cross-reference to Math & Geometry).
19. **Meet in the middle and search-space splitting.** Meet in the middle: subset sums split in two halves (sort one half, binary search or two-pointer the other); partition into two arrays minimising the difference; closest subset sum to a target; 4Sum / 4SumII by pairing sums (hash of pair sums); split array with the same average; knapsack with huge weights; baby-step giant-step (discrete log, name); bidirectional BFS (cross-reference to Graphs); sqrt decomposition (blocks for queries, cross-reference to data structures); splitting the search by constraint (branch on the smaller side); two-sum family (hash / sort and two pointers / binary search) as the one-level case.
20. **Two-pointer, sliding and sweep techniques (cross-reference).** Opposite-end two pointers on a sorted array (two sum, 3Sum, 4Sum, container, squares of a sorted array); same-direction fast / slow (in-place removal, partition); merge-style two pointers over two sorted sequences; sliding window: fixed / variable / at-most-k; monotonic deque for window extrema; sweep line over sorted events (intervals, skyline, meeting rooms); two pointers vs binary search as the choice when counting pairs under a bound; prefix sums with sort; dedupe after sorting. Existing lessons: Two Pointers, Sliding Window, Intervals.
21. **Divide and conquer.** Template: split, solve, combine; master theorem (the three cases, the Akra-Bazzi footnote, reading recurrences like T(n) = 2T(n/2) + n, 3T(n/2) + n, T(n/2) + 1); merge sort and quicksort as D&C; maximum subarray (D&C with crossing sum, Kadane as the O(n) answer); closest pair of points (strip of width 2d, sort by y once); counting inversions (cross-reference group 11); skyline problem (merge two skylines); Karatsuba multiplication (three half-size products); Strassen matrix multiplication (seven products); fast exponentiation / matrix exponentiation (cross-reference to Math & Geometry); FFT / number-theoretic transform for polynomial multiplication (cross-reference, names only); construct a tree from traversals / quad tree / sorted array to balanced BST (D&C on index ranges); majority element by D&C; median of two sorted arrays; merge k lists pairwise; convex hull by D&C (names); Cartesian tree by recursion on the maximum; D&C optimisation of DP (monotone argmin, names); quickselect / median of medians (group 12); Josephus by recursion; the "reduce to a subproblem of half the size" family (pow, sqrt, binary search).
22. **Randomized algorithms I: sampling and shuffling.** Fisher-Yates (Knuth) shuffle (the unbiased inside-out form, and why naive swap-with-any-index is biased); uniform random pick from an array with O(1) insert / delete (swap with last); reservoir sampling: size 1 / size k (algorithm R, stream of unknown length, linked list random node); weighted sampling (prefix sums plus binary search, random pick with weight); weighted sampling without replacement (exponential keys, Efraimidis-Spirakis, names); alias method (Vose, O(1) draw after O(n) setup); rejection sampling (random in a disc, random from 1..n via 1..7); random pick with blacklist (remap to the tail); random point in rectangles (area-weighted); sampling from a distribution given by a CDF; building a uniform generator from a biased coin / from rand7 (rejection and von Neumann); random permutation / derangement; random seed and reproducibility in tests.
23. **Randomized algorithms II: analysis and data structures.** Monte Carlo vs Las Vegas (one-sided / two-sided error, amplification by repetition); random pivot and randomized quickselect (expected linear time, no adversarial input); randomized hashing (universal hash families, random seed per table, polynomial rolling hash as Rabin-Karp, anti-hash tests); Bloom filter and count-min sketch (false positives, names, cross-reference to design problems); skip list (random levels, expected O(log n), the geometric coin flip); treap (random priorities, rotations / split-merge, expected balance); randomized incremental construction (convex hull, closest pair, names); Karger's min cut (graph cross-reference); Miller-Rabin primality (Monte Carlo, cross-reference to Math & Geometry); Freivalds' matrix product check; polynomial identity testing (Schwartz-Zippel); random walks and Markov chains (PageRank, gambler's ruin: names and when they appear); randomised load balancing (power of two choices); probabilistic analysis tools (linearity of expectation, indicator variables, coupon collector).
24. **Approximate and heuristic algorithms.** Greedy approximations (vertex cover via maximal matching: 2-approximation; set cover: ln n; metric TSP via MST: 2-approximation; bin packing first-fit; load balancing / list scheduling: LPT); local search (2-opt, k-opt, swap neighbourhoods); hill climbing (and random restarts); simulated annealing (temperature schedule, acceptance probability); genetic algorithms (selection, crossover, mutation); tabu search; beam search (names); branch and bound (pruning by a bound); A* and heuristic search (admissible / consistent heuristics, cross-reference to Graphs); PTAS / FPTAS (knapsack scaling, names); hardness vocabulary (NP-hard, inapproximability, names only). When they appear: optimisation contests (AtCoder heuristic, Google Hash Code, Kaggle), scheduling and packing in production, and the interview question "what if exact is too slow?". Almost never on LeetCode, so the lesson is naming and when to reach for each.
25. **Amortised analysis patterns.** The three methods: aggregate / accounting (banker's) / potential; dynamic array (doubling gives O(1) amortised append, growth factor and shrink hysteresis); two stacks as a queue (each element moves once); binary counter increment (O(1) amortised, bit flips); monotonic stack and deque (each element pushed and popped once); sliding-window two-pointer (each pointer moves n times); union-find with path compression (inverse Ackermann, cross-reference); splay trees and self-adjusting structures (names); hash table resize (rehash cost amortised); Fibonacci heap decrease-key (O(1) amortised, names); ring buffer / circular queue; lazy deletion in heaps (stale entries); persistent vs amortised bounds caveat (worst-case spikes); the potential function recipe with a worked example for each.
26. **Online algorithms.** Online vs offline and the competitive ratio; secretary problem (observe n/e then take the first better, 1/e success); ski rental (rent until the cost equals the purchase price: 2-competitive; randomised e/(e-1)); paging and caching: LRU / FIFO / LFU are k-competitive, Belady's optimal offline policy as the benchmark (LRU cache and LFU cache problems); online bipartite matching (RANKING, names); online stock span and streaming statistics (running median, moving average); scheduling online (list scheduling 2-competitive); load balancing; the k-server problem and list update (names); streaming algorithms (one pass, sublinear memory: reservoir sampling, Boyer-Moore, count-min, HyperLogLog, cross-reference to groups 13 and 22); adversary arguments for lower bounds.
27. **Core implementation patterns.** Stability (keep original index as tie-break, compare keys only); comparator contracts (strict weak ordering: irreflexive, antisymmetric, transitive; a broken comparator makes sort panic or loop; never subtract ints in a comparator, compare); integer overflow in mid (`lo + (hi - lo) / 2`, unsigned vs signed, Rust `checked_add`, the famous 2006 bug); off-by-one in loops (closed vs half-open, `lo < hi` vs `lo <= hi`, shrinking so the loop always progresses); infinite loop when `mid` rounds down and `lo = mid`; loop invariant first, then code; sentinel values and `inf` bounds; coordinate compression (sort, dedup, map to rank); sorting indices instead of values (argsort); sorting with a key vs with a comparator; in-place vs copy and aliasing in partition; recursion depth limits in quicksort / merge sort; iterative versions to avoid stack overflow; floating-point comparison with epsilon; random number generator choice and seeding; testing a sort or search against a brute-force oracle with random inputs (property tests).
