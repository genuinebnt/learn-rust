How to Use This Packet
Suggested 2-week study plan
Every day · Warm-up drills
Before anything else, do 3–5 items from the Syntax & Algorithm Drills page — on paper or a bare editor, no IDE/LSP. This is what builds the muscle memory that makes syntax invisible in a live interview.
Days 1–3 · Foundations
Topics 01 (Ownership → Lifetimes). Do W1–W3 write exercises. These are the questions that eliminate candidates in the first 10 minutes if shaky.
Days 4–6 · Type system
Topics 02 (Traits → Smart Pointers). Do B1, B2, W6. Focus on articulating why you'd choose static vs dynamic dispatch.
Days 7–10 · Concurrency & web
Topics 03 (Threading → Crates). Do B3, B6, W4, W5, W7. This is where most Rust job descriptions concentrate — Tokio + web frameworks.
Days 11–13 · Senior + system design
Topics 04 + all 18 design-pattern write exercises, 24 system-design scenarios. Practice narrating trade-offs out loud — this is what a staff/senior debrief actually evaluates.
Day 14 · Mock & scorecard
Have a friend (or yourself, out loud) run through the bug and write exercises cold. Fill out the self-assessment scorecard honestly — target areas below 3/5.
How the Q&A widgets work: click any question row to expand the model answer inline. Bug and write exercises hide their solution key under a collapsible arrow — try to solve it yourself first, then reveal. Use the level filter bar at the top of each topic page to focus your remaining time.
What "senior" answers sound like — regardless of topic
States the trade-off before being asked. "I'd use Arc<Mutex<T>> here, but if this becomes a hot path I'd switch to sharding the lock or using an RwLock for read-heavy access."
Reasons about failure modes, not just the happy path. "What happens if this task panics inside a Tokio task? The JoinHandle returns an error, but nothing else is torn down automatically."
Knows the cost model. Can estimate allocation counts, lock contention, or cache-line behaviour without running a profiler first — then verifies with one.
Pushes back on the question when it's underspecified. "Is this single-writer-multi-reader or could there be concurrent writers? That changes whether I reach for RwLock or a channel-based design."
Distinguishes "idiomatic" from "clever." Prefers the boring, obviously-correct solution and can articulate why cleverness is a liability in shared codebases.
Has opinions about tooling. Mentions cargo clippy, miri, loom, or cargo-flamegraph unprompted when discussing correctness or performance work.

Toolchain & Ecosystem Cheat Sheet
Commands you should be able to explain, not just run
Command What it does / why it matters in interviews
rustupToolchain manager — installs/switches Rust versions and components (rustfmt, clippy). Interviewers may ask how you'd pin an MSRV (minimum supported Rust version) via rust-version in Cargo.toml.
cargo build --releaseCompiles with optimisations (opt-level=3, LTO configurable). Debug builds are unoptimised and much slower at runtime — never benchmark debug builds.
cargo clippyLinter beyond the compiler — catches non-idiomatic patterns, needless clones, inefficient string ops. Senior candidates run this as part of CI, not as an afterthought.
cargo fmtCanonical formatter — removes bikeshedding from code review. Almost every serious Rust team enforces this in CI.
cargo testRuns unit + integration tests (files under tests/) + doc-tests (examples in /// comments actually get compiled and run).
cargo bench / criterionMicro-benchmarking. Built-in #[bench] requires nightly; criterion crate is the stable, statistically rigorous standard.
cargo expandShows macro-expanded code — essential for debugging derive macros, #[tokio::main], or your own proc-macros.
cargo miri runInterpreter that detects undefined behaviour in unsafe code — dangling pointers, invalid alignment, data races on raw pointers. A senior signal is knowing this exists.
cargo auditScans Cargo.lock against the RustSec advisory database for known-vulnerable dependency versions.
cargo treePrints the dependency graph — useful for finding duplicate versions of a crate bloating your binary or causing type mismatches across versions.
LoomConcurrency permutation-testing crate — exhaustively explores thread interleavings for a piece of lock-free/atomic code in tests. The tool senior candidates reach for when writing custom sync primitives.
WorkspacesA root Cargo.toml with [workspace] members = [...] — multiple crates sharing one Cargo.lock and target directory. Standard for any non-trivial service (separate lib, cli, api crates).
Editions & versioning — know the difference
Rust edition (2015 / 2018 / 2021 / 2024) is a language-syntax opt-in, set per-crate in Cargo.toml, that allows breaking changes to syntax (e.g. 2018 added the module system overhaul; 2021 changed closure capture and added IntoIterator for [T; N]; 2024 tightened unsafe ergonomics and RPIT lifetime capture rules) without breaking the wider ecosystem — different editions link together fine in the same binary. Rust release channel/version (stable/beta/nightly, e.g. 1.79) is the compiler version — new language features and standard library APIs land here first on nightly, stabilise onto stable roughly every 6 weeks. MSRV is a crate's promise about the oldest compiler version it supports — important for library crates since bumping MSRV is a breaking change for downstream users on older toolchains.
